# 文件生成流程统一进度浮层设计规格

## 目标

文件生成处理不再打开独立 macOS 进度窗口，改用与导入流程一致的主窗口内非模态浮层交互。执行期间用户可继续查看预览与日志，并可从浮层取消流程。

## 方案

将现有导入进度浮层的表面、展开/收拢动画、成功自动关闭、失败停留、实时区域和代次控制抽成可复用能力。导入流程继续保持当前表现；文件生成流程使用同一交互核心，并锚定到“全部执行”分割按钮。

生成浮层显示当前步骤、当前文件或计数以及进度。执行中提供“取消”按钮；取消请求只触发现有 `CancellationTokenSource`，不改变进程终止和输出清理语义。成功短暂停留后自动收起；失败保留错误信息并显示“关闭”。

## 状态与进度

- 准备/第 1 步/第 3 步可使用不确定进度。
- 第 2 步逐层生成 DXF 时显示当前层文件名和 `当前/总数` 确定进度。
- 全部流程显示“步骤 1/3、2/3、3/3”；单步流程显示对应步骤名称。
- 成功状态概括本次生成结果；取消状态写入日志后收起；失败状态显示异常信息。
- 状态变化通过自动化实时区域播报，但同一阶段的逐项更新不重复播报。

## 范围

- 重构进度浮层为导入与生成流程共用的交互基础。
- 将 `RunPipelineAsync` 从 `ProcessingProgressWindow` 迁移到生成浮层。
- 保留并接入现有取消、日志、预览更新和按钮启用状态。
- 删除不再使用的独立生成进度窗口。
- 增加状态、动画、取消、成功、失败和结构回归测试。
- 重新构建并打开 macOS 应用。

不改变 Python 脚本、生成顺序、文件校验、残留清理策略、参数语义或输出目录规则。

## 验收标准

1. 全部执行及三个单步操作均不再打开独立窗口。
2. 生成浮层锚定在“全部执行”按钮附近，且主窗口保持可操作。
3. 第 2 步逐层显示确定进度；其他无法可靠计数的阶段显示不确定进度。
4. 取消按钮可以终止现有流程，并恢复所有主界面按钮状态。
5. 成功后自动收起；失败时停留并可关闭。
6. 导入浮层现有行为不退化。
7. 自动化测试与 macOS 应用构建通过。

## 风险与验证

主要风险是早期 `return` 跳过成功状态、取消与成功自动关闭互相竞争，或导入/生成共用逻辑后发生状态串扰。两个流程使用独立浮层实例和独立代次；生成结果在 `finally` 恢复界面状态，终态在退出前统一提交。测试覆盖提前返回、取消、异常及连续执行。
