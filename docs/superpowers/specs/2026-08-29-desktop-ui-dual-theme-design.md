# 桌面工作台原布局 UI 精修与黑白双主题设计

日期：2026-08-29  
状态：设计已确认，等待书面规范复核  
适用项目：`GrayscaleLayersMac`

## 修订原因

上一版实现主要完成了主题基础设施、颜色令牌和少量表面调整，但没有把“打开应用即可看出变化”作为硬性验收条件。结果是代码和测试发生了变化，主界面的轮廓、控件质感和日常操作体验仍与原版过于接近。

本版规范替代上一版方案。它保留用户已经熟悉的操作逻辑，在原有布局上重做控件样式、工具排列、图标、菜单、状态反馈和浅深主题细节。任何会改变参数浏览方式或三步工作流的结构重排均不在本次范围内。

## 用户目标

用户需要继续以原来的方式完成以下任务：

1. 在右侧选择原始图片和输出目录。
2. 按原顺序查看或修改灰度分层、Hatch 与 DXF、Voronoi 和机器参数。
3. 在左侧切换纹理与 DXF 预览并操作图层、缩放和视图。
4. 从固定执行区运行全部流程或单独步骤。
5. 在原位置查看和折叠日志。

优化后的界面应让这些操作更清晰、更精致、更接近 macOS 专业工具，但不能要求用户重新学习工作流。

## 设计目标

1. 保留现有左右分栏、参数顺序、折叠结构、预览位置、日志位置和执行逻辑。
2. 让顶部工具、下拉框、按钮、输入框、参数卡片、菜单和小型图标产生清晰可见的视觉变化。
3. 提供完整的“跟随系统 / 浅色 / 深色”外观模式，默认跟随 macOS。
4. 用共享语义令牌和组件样式覆盖所有常见状态，避免窗口代码零散硬编码主题色。
5. 采用 Apple 风格的即时反馈、空间一致性、克制材质和平台字体层级。
6. 完成键盘焦点、VoiceOver 名称、对比度和减少动态效果支持。
7. 建立逐区域截图复核机制，避免实现结束后才发现界面几乎没有变化。

## 非目标

- 不改变左右工作区的主从关系或默认分栏比例。
- 不把右侧参数区改成分类页签、步骤向导或一次只显示一组参数的检查器。
- 不改变任何参数名称、含义、默认值、解析方式或执行顺序。
- 不改变文件选择、缓存、预览、日志、Python 管线或输出目录逻辑。
- 不新增预览区中央导入按钮。
- 不引入大面积玻璃、弹跳动画、装饰性插画或新的品牌视觉。
- 不为了“看起来不同”而牺牲信息密度或隐藏常用操作。

## 不可变的操作结构

以下结构必须保持：

- 左侧为纹理与 DXF 预览，右侧为参数检查器。
- 右侧参数保持“灰度分层 / Hatch 与 DXF / Voronoi / 机器加工文件”的现有顺序。
- 各参数组继续使用纵向折叠结构，并允许用户同时展开多个分组。
- “纹理 / DXF”继续在预览顶部切换。
- “全部执行”继续使用分割按钮，附加菜单继续提供三个单步操作。
- “打开加工文件目录”继续作为次级操作，仅在输出可用时启用。
- 日志继续位于原区域，并保留折叠、清空和状态记忆。
- 用户已有的分栏、侧栏与日志折叠偏好继续兼容。

## 可见改造范围

### 顶部栏与工具排列

- 保留应用图标、名称和流程副标题，但降低品牌区的视觉重量。
- 在现有顶部区域内重新组织工具，使“导入、清缓存、外观”成为对齐一致的紧凑工具组。
- 顶部栏高度和整体工作区结构不做大幅改变，避免内容跳动。
- 工具组内使用统一高度、间距和图标基线；危险或清理操作不与主要导入操作争夺视觉焦点。
- 外观按钮继续显示当前选择，并通过菜单提供“跟随系统 / 浅色 / 深色”。

### 按钮体系

按钮分为四级：

1. 主按钮：仅用于“全部执行”，使用实心蓝色、白色文字和明确按压反馈。
2. 次级按钮：用于选择图片、选择目录和打开输出目录，使用轻底色或描边。
3. 安静按钮：用于导入菜单、外观和低频工具，默认弱化，悬停时显现表面。
4. 图标按钮：用于缩放、适合窗口、清空和折叠等小操作，使用真实矢量图标和 Tooltip。

所有按钮必须覆盖默认、悬停、按下、键盘焦点、禁用和危险状态。指针按下时立即出现颜色与轻微压缩反馈，释放时才提交操作；普通按钮不使用弹跳。

### 下拉框与弹出菜单

- 下拉框使用 34–36pt 统一高度、8pt 圆角和一致内边距。
- 选中值与箭头保持清晰的左右结构；箭头使用真实矢量图标，不使用字符符号。
- 默认边框保持克制，悬停时边框增强，键盘焦点显示蓝色焦点环。
- 弹出菜单从触发控件附近展开，空间来源明确。
- 当前选项同时使用对勾、字重和淡蓝背景表达，不只依赖颜色。
- 菜单项、分割线、内边距和圆角在浅色与深色主题中分别校准。

### 输入框、数字框与复合路径字段

- 文本框、数字框、下拉框和次级按钮采用统一的垂直尺寸与圆角。
- 标签、单位、输入值和按钮基线对齐；既有字段列数和排列顺序不变。
- 文件路径输入与选择按钮继续作为复合字段呈现，不改变文件选择方式。
- 输入框必须提供默认、悬停、焦点、只读、禁用和错误状态。
- NumericUpDown 的增减按钮使用与其他小操作一致的图标、触发区域和悬停反馈。
- 长路径允许省略显示，但 Tooltip 或现有读取方式必须保留完整值。

### 参数折叠卡片

- 各参数组继续纵向排列并保持现有展开逻辑。
- 卡片使用 12pt 圆角、轻边框和明确但克制的表面层级。
- 标题行不再依赖厚重深色块；通过字重、留白、轻微背景差和折叠箭头表达结构。
- 折叠箭头使用统一图标，旋转方向必须与展开状态一致。
- 标题行整行可点击，同时保留键盘操作和自动化语义。
- 卡片内容采用统一的 8pt 间距节奏；允许 4pt 用于紧凑内部关系。
- 常用与高级参数的默认展开状态保持现有行为，本次不引入新的分类导航。

### 预览工具与分段控件

- “纹理 / DXF”保持原位置和语义，改成带外壳的胶囊分段控件。
- 选中项同时使用背景、描边和字重；未选中项降低视觉重量。
- 图层、缩放、适合窗口、保持视图及其他现有工具不改变功能和顺序。
- 小操作使用同一套线性图标，图标尺寸、描边和按钮目标区域保持一致。
- 图标按钮目标区域至少 30–32pt，并提供 Tooltip、键盘焦点和 VoiceOver 名称。
- 预览画布仍是最深或最下沉的工作表面，不能被卡片装饰抢走注意力。

### 日志与执行区

- 日志继续位于原位置，保留现有折叠和状态持久化。
- 折叠把手、标题、最新消息和清空按钮统一到新的按钮与图标体系。
- 日志内容继续使用等宽字体和下沉表面，但边框、内边距与浅色主题需要重新校准。
- 底部执行区保持固定位置和原有按钮排列。
- 准备状态继续说明缺失项、执行中和已准备状态；状态颜色必须走语义令牌。
- 主执行、次级打开目录和危险取消操作形成清晰层级。

## 尺寸与排版

- 使用平台系统字体；日志和数值场景继续使用等宽字体。
- 常规输入、下拉框和次级按钮高度为 34–36pt。
- 紧凑图标按钮目标区域为 30–32pt。
- 主执行按钮高度保持 44pt。
- 卡片圆角为 12pt；输入和常规按钮圆角为 8pt；分段控件外壳圆角为 9pt。
- 间距以 8pt 为主节奏，4pt 用于紧密关联元素，12pt 或 16pt 用于分组分隔。
- 标题通过字号、字重和行高建立层级；正文不统一添加额外字距。
- 小型分区标签可使用轻微正字距，大标题不得使用明显扩张字距。

## 黑白双主题

### 语义令牌

共享令牌至少包含：

- 窗口、顶部栏、检查器、卡片、下沉表面和弹出层背景。
- 主要、次要、弱化和禁用文字。
- 轻、中、强边框。
- 强调色、悬停、按下、选中背景和强调色前景。
- 焦点环、禁用背景、危险、警告、成功和信息状态。
- 图标默认、悬停、按下和禁用状态。

错误、警告或完成状态不得继续直接使用 `OrangeRed` 等硬编码画刷。DXF 图层、加工方向和纹理内容属于数据颜色，可以保留独立调色板，但必须在两种画布背景上可辨认。

### 深色主题

- 使用石墨黑窗口与蓝灰表面，不堆叠大块纯黑。
- 输入框、菜单和下沉区域比卡片更深，但边界不能依赖高对比白线。
- 蓝色用于普通交互，橙色只用于警告或领域数据。

### 浅色主题

- 窗口使用暖白，卡片使用冷白，输入和画布使用浅灰蓝下沉表面。
- 菜单、边框、禁用和只读状态必须单独校准，不能简单反转深色颜色。
- 不给每张卡片增加明显阴影；顶部栏和弹出菜单允许极轻的层级阴影或半透明材质。

## Apple 风格交互原则

- 反馈从指针按下开始，不等待点击结束才显示。
- 操作仍在释放时提交，允许用户按下后移出目标取消操作。
- 菜单和弹出层从触发控件附近出现，进入与退出遵循相同空间路径。
- 折叠、菜单和状态变化必须可以被反向操作，不能在动画期间锁住输入。
- 普通控件使用克制、无弹跳的短反馈；只有真实动量操作才允许弹性效果，本应用本次不新增此类效果。
- 大面积透明材质不进入参数内容区；材质只用于帮助表达工具栏与菜单层级。

## 动态效果与辅助设置

- 按钮颜色和边框反馈建议为 100–140ms。
- 折叠与日志展开建议为 180–220ms，路径进入与退出对称。
- 主题切换以颜色更新为主，不移动布局，不丢失焦点和滚动位置。
- macOS 开启减少动态效果时，取消缩放、旋转和位移动画，仅保留即时切换或短淡入淡出。
- 若无法可靠读取系统减少动态效果设置，应提供集中式运动开关并默认采用最克制的动画。

## 可访问性

- 普通文字至少达到 4.5:1；大文字和非文字控件按适用标准验证。
- 主按钮、次要文字、输入边界、禁用状态、错误状态和焦点环必须分别在浅色与深色下测试。
- 选中、错误、警告和成功状态不得只依赖颜色。
- Tab 顺序与视觉顺序一致；所有按钮、下拉框、Expander、分割按钮、GridSplitter 和日志把手可通过键盘触达。
- 为图标按钮、外观菜单、折叠按钮、分隔条和主操作提供明确的自动化名称。
- VoiceOver 应能读出控件名称、当前状态和必要的操作结果。
- 主题切换不得清除当前焦点、表单值、滚动位置或分栏比例。

## 代码边界与数据流

- `UiTheme` 或同等样式层负责语义令牌、主题调色板、控件状态和公共尺寸。
- 控件工厂只选择组件层级和类名，不直接持有主题相关 RGB 值。
- `MainWindow` 保留现有业务事件和布局顺序，只调整工具排列并接入共享样式。
- 图标资源集中管理，禁止在窗口代码中散布临时字符图标或重复路径数据。
- `AppAppearance` 继续负责 `System / Light / Dark` 选择；设置层继续负责持久化和无效值回退。
- 主题变化更新共享画刷和控件资源，不重建窗口或业务控制器。
- 预览控件通过主题变化事件重绘画布背景、网格、文字和数据颜色。
- 运动偏好由集中式设置解析，组件只能读取统一结果。

## 错误与回退

- 外观设置缺失或无效时回退 `System`，不能阻止应用启动。
- 无法读取系统主题时回退深色并写入非阻塞日志。
- 新的共享样式或图标资源缺失时，控件回退 Avalonia Fluent 默认外观，业务事件仍可执行。
- 单个预览画刷更新失败时，通用界面继续完成主题切换，并在下一次重绘恢复预览。
- 样式改造不得改变磁盘文件、缓存所有权、管线输入或输出。

## 自动化测试

保留现有测试，并新增：

- 所有必需语义令牌在浅色与深色中均存在。
- 主文字、次要文字、按钮文字、菜单选中项、错误文字和焦点环达到目标对比度。
- 按钮、下拉框、输入框、菜单、Expander 和分段控件包含规定的状态样式。
- `System / Light / Dark` 解析、持久化和无效值回退。
- 系统主题变化只影响 `System` 模式；手动模式保持不变。
- 重新创建窗口后恢复外观选择、分栏和已有折叠状态。
- 主题切换不改变表单值、当前预览类别和准备状态。
- 图标按钮具有 Tooltip 和自动化名称。
- 减少动态效果开启时不安装位移、旋转或缩放动画。
- 原有管线、文件选择、预览、日志和执行模式测试继续通过。

## 视觉与交互验收

### 必须捕获的状态

1. 1440×940 深色默认状态。
2. 1440×940 浅色默认状态。
3. 1080×720 深色最小窗口。
4. 1080×720 浅色最小窗口。
5. 下拉菜单和外观菜单打开状态。
6. 主按钮、次级按钮和图标按钮的悬停、按下、焦点与禁用状态。
7. 输入框和数字框的焦点、只读、禁用与错误状态。
8. 参数卡片展开与折叠状态。
9. 导入完成、执行中、失败和完成状态。
10. 长路径、长中文错误文本和日志折叠状态。

### 对比方式

- 每个主要区域修改后立即运行应用并截图，不等待全部实现完成。
- 改造前与改造后使用相同窗口尺寸、主题和内容状态。
- 对比顶部工具排列、控件高度、圆角、边框、字体、间距、图标、菜单和状态反馈。
- 截图只能证明可见结果；键盘、VoiceOver、减少动态效果和焦点保持必须通过实际交互验证。

## 完成标准

只有同时满足以下条件，任务才可标记完成：

1. 用户原有操作路径、参数顺序和业务行为不变。
2. 顶部工具排列、下拉框、按钮、输入框、参数卡片、分段控件、菜单和小型图标均完成统一改造。
3. 在相同尺寸的前后截图中，不放大图片也能明确辨认出上述变化。
4. 浅色与深色不仅背景不同，控件全部状态也分别校准。
5. 小操作使用真实图标、Tooltip 和自动化名称，不使用文本字符冒充图标。
6. 主题颜色无散落硬编码；状态颜色全部来自语义令牌。
7. 键盘、VoiceOver、对比度和减少动态效果完成验证。
8. 默认窗口、最小窗口及所有规定状态无裁切、重叠、错误对齐或不可读文字。
9. 所有自动化测试和 macOS 应用包验证通过。
10. 视觉证据与测试结果随实现一起交付，不能仅以代码变更声明完成。
