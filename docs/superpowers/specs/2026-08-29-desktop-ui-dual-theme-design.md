# 桌面工作台 UI 精修与黑白双主题设计

日期：2026-08-29  
状态：设计已确认，等待书面规范复核  
适用项目：`GrayscaleLayersMac`

## 背景

纹理预处理工具是一个 Avalonia/macOS 桌面工作台。主界面采用左侧预览、右侧参数检查器、底部日志和固定执行栏的布局，服务于灰度分层、Hatch DXF 生成与机器加工文件打包。

本次实际截图审查确认，现有信息架构适合高密度生产任务，但视觉层级依赖大面积深色和重复边框；右侧检查器可扫读性偏弱；橙色选中态与蓝色主操作形成两套强调色；浅色主题及系统外观同步尚未形成完整体系。

审查证据与完整记录位于 `design-audit/audit.md`。

## 目标

1. 保留现有工作流语义与双栏工作台结构，提升视觉层级、可扫读性和 macOS 平台一致性。
2. 提供完整的浅色与深色主题，默认跟随 macOS 系统外观，并允许用户手动覆盖。
3. 用一套共享的语义设计令牌驱动两种主题，避免组件各自硬编码颜色。
4. 统一选中、焦点、进度与主操作的视觉语言。
5. 改善键盘、VoiceOver、对比度和减少动态效果支持。

## 非目标

- 不新增预览区中央的导入按钮；导入继续从右侧顶部工具区进入。
- 不改变灰度分层、DXF 和机器加工文件的业务流程与参数语义。
- 不把右侧检查器改造成新的步骤导航或多页面向导。
- 不重做预览渲染、DXF 图层逻辑、文件选择流程或 Python 管线。
- 不引入大量透明玻璃、弹跳动画、装饰性图形或新的品牌资产。

## 选定方向

采用“系统化精修”方案：保留现有双栏比例、可拖拽分隔条、折叠日志和固定执行区，在此基础上统一视觉令牌、调整参数卡片层级、集中顶部工具、增加准备状态，并实现系统外观同步与手动覆盖。

没有选择仅换色方案，因为它无法解决强调色冲突和检查器层级问题。没有选择结构重排方案，因为它会改变熟练用户同时查看全部参数的工作方式，范围与风险均超过本次目标。

## 视觉系统

### 语义令牌

组件不得直接使用主题相关 RGB 值。主题至少提供以下语义角色：

- `WindowBackground`：应用最底层窗口背景。
- `ChromeBackground`：顶部品牌栏与底部执行栏。
- `InspectorBackground`：右侧检查器结构面。
- `SurfaceBackground`：参数卡片和常规浮起表面。
- `SunkenBackground`：预览画布、日志与输入框的下沉区域。
- `TextPrimary`、`TextSecondary`、`TextTertiary`：三级文字。
- `BorderSubtle`、`BorderStandard`、`BorderStrong`：三级边界。
- `Accent`、`AccentHover`、`AccentPressed`、`AccentForeground`：交互强调。
- `Warning`、`Danger`、`Success`：状态语义。
- `FocusRing`、`SelectionBackground`、`DisabledForeground`、`DisabledBackground`：交互状态。

预览内容颜色、DXF 线条、加工块颜色和方向箭头属于数据可视化令牌，不与通用按钮强调色共用。橙色仅保留给警告或加工方向等领域信息。

### 深色主题

- 采用近黑石墨背景与轻微蓝灰表面层级，不使用大块纯黑互相切割。
- 卡片主要依靠背景明度、间距和轻边框分层。
- 文字优先保证长时间工作下的清晰与舒适，三级文字都必须达到预定对比度。
- 预览画布保持最深层，明确其作为内容工作区而不是普通卡片。

### 浅色主题

- 窗口使用暖白，检查器和卡片使用冷白或极浅灰，避免所有表面堆叠为刺眼纯白。
- 下沉区域采用浅灰蓝背景，边界略深于周围表面。
- 阴影只用于顶部和底部浮层，不给每张参数卡片增加明显投影。
- 预览内容和方向色需要针对浅色背景单独校准。

### 排版与尺寸

- 默认使用平台系统字体。
- 页面或工作台标题使用中等字重并适度收紧字距；小型分区标签可轻微增加字距；正文不统一设置额外字距。
- 采用 8pt 间距节奏，允许 4pt 作为紧凑内部间距。
- 常规卡片圆角为 10–12pt，输入和按钮圆角为 7–9pt。
- 小型桌面工具按钮的目标区域至少约 28–32pt；主操作保持当前 44pt 高度。

## 信息组织与组件

### 顶部品牌栏

- 保留应用图标、名称和英文流程副标。
- 将导入、清缓存和外观菜单集中在检查器顶部工具区，不把工具塞入品牌栏中央。
- 外观菜单提供“跟随系统”“浅色”“深色”，明确当前选择。

### 预览区

- 保留当前安静的空状态，不新增中央导入按钮。
- “纹理 / DXF”改为统一的分段选择器。选中态同时使用背景、描边和字重，不只依赖颜色。
- 图层、缩放、滚轮模式和保持视图等现有工具保持原有语义和位置关系。
- 预览工具栏、状态行与画布采用更明确的层级，但不增加新的步骤提示。

### 检查器顶部状态

- 在顶部工具区与首个参数分组之间显示紧凑的准备状态。
- 状态根据现有输入值列出缺失项，如原始图、分层目录或 DXF 目录。
- 状态只做汇总，不替代字段附近的错误说明。
- 当全部必要输入满足时显示明确的“已准备”文本，而不是仅解除按钮禁用。

### 参数分组

- 保持现有“灰度分层 / Hatch 与 DXF / Voronoi / 机器参数”等顺序和字段内容。
- 折叠标题改为较轻的实色标题行，通过字重、留白和箭头表达结构，减少大块纯黑。
- 常用分组默认展开；高级分组沿用或新增持久化的上次展开状态。
- 文件路径字段与选择按钮作为一个复合字段呈现。
- 数值字段统一标签、单位、输入高度和列对齐；单位保留在标签中，不改变现有解析逻辑。

### 底部执行栏

- 保留固定底部布局和“全部执行”分割按钮。
- 分割菜单仍提供单步执行，既有运行模式语义不变。
- 执行栏同时展示当前执行范围或准备状态，使禁用原因可见。
- “打开加工文件目录”继续作为次级按钮，只有输出可用时启用。

### 日志栏

- 保留可折叠行为、状态记忆和清空操作。
- 视觉上使用下沉表面，与预览画布形成一致的工具工作区语言。
- 折叠把手提供悬停、按下和键盘焦点反馈。

## 主题状态与数据流

新增外观选择枚举：

- `System`
- `Light`
- `Dark`

数据流如下：

1. 启动时从工作区设置读取外观选择；缺失或无效值回退为 `System`。
2. `System` 模式解析当前 macOS/Avalonia 平台主题，并监听后续系统外观变化。
3. `Light` 或 `Dark` 模式直接应用指定主题，系统变化不覆盖手动选择。
4. 主题管理器把选择解析为有效主题，再更新应用级语义资源。
5. 控件只绑定语义资源；主题变化后由资源系统统一刷新。
6. 用户选择立即生效，并通过现有工作区设置机制持久化。

主题解析、设置持久化与控件构建分离：主题管理器负责状态与资源，设置类负责读写，`UiTheme` 负责令牌与共享控件样式，`MainWindow` 只创建外观菜单并响应用户选择。

## 交互与动态效果

- 按钮在指针按下时立即给出背景或轻微尺度反馈，操作仍在释放时提交。
- 普通按钮反馈不使用弹跳。
- 分组折叠、日志展开和主题切换使用约 180–240ms 的短过渡，并能从当前视觉状态反向执行。
- 主题切换以颜色交叉变化为主，不移动大面积内容。
- 系统启用减少动态效果时，取消位移和缩放，仅保留必要的短颜色变化或即时切换。
- 所有进入与退出遵循同一路径，避免折叠和展开方向不一致。

## 可访问性

- 分别验证浅色和深色主题中的普通文字、次要文字、输入边界、禁用状态、焦点环和主按钮对比度。
- 选中、错误、警告和成功状态同时使用文字、形状或图标语义，不能只靠颜色。
- 为按钮、分段选择器、Expander、GridSplitter 和日志把手提供清晰键盘焦点样式。
- 核对 Tab 顺序与视觉顺序一致，所有可操作项可通过键盘触达。
- 为外观菜单、折叠按钮、分隔条和图标按钮提供明确的自动化名称，供 VoiceOver 使用。
- 主题改变后，焦点位置与当前操作状态不丢失。

## 错误与回退

- 保存的外观值缺失、无法解析或版本不兼容时回退 `System`，不能阻止应用启动。
- 无法读取系统主题时使用深色主题作为稳定回退，并记录非阻塞日志。
- 主题切换过程中单个可视化画刷刷新失败时，通用界面资源仍需完成切换；预览层可在下一次重绘恢复。
- 准备状态只基于现有输入与运行状态计算，不引入新的磁盘扫描或耗时校验。
- 任何主题错误都不得改变管线输入、输出路径或加工参数。

## 代码边界

预期调整集中在以下区域：

- `UiTheme.cs`：语义令牌、浅深主题资源、共享控件样式和动态效果。
- 新的主题状态/管理单元：外观枚举、系统主题解析和有效主题应用。
- `WorkspaceSplitSettings.cs` 或同等设置层：外观选择与高级分组展开状态持久化。
- `MainWindow.cs`：外观菜单、准备状态、顶部工具组织与组件样式接入。
- 相关预览和日志组件：移除硬编码主题颜色，接入语义资源与焦点样式。

不在本次范围内重构业务管线方法或预览数据模型。

## 测试策略

### 自动测试

- 外观选择序列化、反序列化、无效值回退和默认 `System`。
- `System / Light / Dark` 到有效主题的解析。
- 系统主题变化只在 `System` 模式生效。
- 手动主题选择持久化并在重新创建窗口后恢复。
- 语义令牌在两套主题中完整存在，不允许组件依赖缺失资源。
- 准备状态在输入缺失、部分满足、全部满足和运行中时输出正确文本。

### 交互验证

- 键盘切换分段选择、展开分组、调整分隔条并操作外观菜单。
- 验证主题切换不改变焦点、滚动位置、分栏比例、折叠状态和表单值。
- 验证系统外观变化即时更新 `System` 模式，手动模式保持不变。
- 用 VoiceOver检查外观菜单、分隔条、折叠按钮和主操作的名称与状态。

### 视觉验证

- 分别捕获浅色和深色的默认空状态、导入完成、执行中、失败和完成状态。
- 在 1440×940 默认窗口与 1080×720 最小窗口检查裁切、滚动、按钮可见性与字段对齐。
- 对长路径、较长中文错误文本、禁用控件和焦点状态做专项截图。
- 将改造前截图与同尺寸改造后截图并排比较，检查边距、字号、圆角、边框和层级是否符合本规范。

## 验收标准

1. 应用提供“跟随系统 / 浅色 / 深色”三种外观选择，默认跟随系统且手动选择可持久化。
2. 两套主题覆盖主窗口、检查器、预览工具、日志、弹出菜单、进度、焦点和禁用状态。
3. 通用交互强调统一为蓝色；橙色不再表示普通选中状态。
4. 右侧卡片标题层级更轻，字段标签、单位和列对齐一致。
5. 检查器顶部和执行栏能够说明缺失项或准备状态。
6. 预览空状态不新增导入按钮。
7. 原有运行模式、参数值、文件路径、分栏、折叠、预览和日志行为保持兼容。
8. 自动测试通过，浅色和深色截图在默认与最小窗口下无明显裁切或对比度问题。
