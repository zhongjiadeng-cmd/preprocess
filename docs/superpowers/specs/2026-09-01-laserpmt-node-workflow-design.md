# LaserPMT 节点工作流设计

## 目标

把现有的 LaserPMT 参数矩阵表单升级为可持久化的节点工作流。基础参数可以整体作用于全部加工目标；用户可以从基础参数中移除某一项，再通过带编号输出端的单参数节点，把逗号分隔的不同参数值连接到指定 PMT 或时间戳。PMT 保留自动创建能力，同时允许单独移动和删除。时间戳作为可加工元素存在于工件内，可编辑、移动和缩放，并生成水平填充的数字 NPY。

节点图是生成输入的唯一真实配置。生成器先把节点和连线编译成每个目标的完整参数及加工计划，再生成独立 PMT 文件、`allmachine.json`、NPY、参数映射表和布局清单。

## 范围

首版支持：

- 一张同时容纳参数节点、工件、PMT、时间戳和连线的无限画布。
- 一个不可删除的基础参数节点。
- 任意数量的单参数节点。
- 独立设置 PMT 数量与每行数量。
- PMT 初始自动布局、单独拖动和单独删除。
- 任意数量的时间戳元素。
- 节点、目标、端口、连线和视口状态的持久化。
- 旧版 PMT 布局的只读打开和显式升级保存。

首版不支持：

- 单参数节点同时表示多个参数名或生成笛卡尔积。
- PMT 单独缩放。
- 时间戳独立机器 JSON。
- 自动修复越界或重叠元素。
- 删除 PMT 后自动重排或复用历史编号。

## 核心架构

### 版本化工作流文档

`pmt-layout.json` 升级为格式版本 2，并同时保存源工作流与编译结果。源工作流包含：

- 基础加工目录的身份信息；
- 工件尺寸、当前项目的 Hatch spacing 和画布视口；
- 节点类型、稳定 ID、位置、参数和端口；
- PMT 的稳定 ID、编号、位置及是否被手动移动；
- 时间戳的稳定 ID、创建顺序、文本、位置、宽度和高度；
- 使用稳定节点、端口和目标 ID 表示的连线；
- 下一个 PMT 编号和下一个元素创建序号。

编译结果包含每个加工目标的最终参数、物理边界、NPY 引用、输出文件和加工顺序。加载文档时必须重新编译源工作流，并验证保存的编译结果与重算结果一致；不一致时拒绝生成。

### C# 工作流领域层

新增不依赖 Avalonia 控件的领域类型，分别负责：

- 节点、端口、目标和连线的数据模型；
- 参数值解析和类型校验；
- 基础继承与单参数覆盖；
- PMT 编号分配、增减和删除规则；
- PMT 初始布局及显式自动重排；
- 元素边界和相交检测；
- 版本 2 文档序列化；
- 生成就绪状态和可定位错误。

工作流编译器接收完整的不可变工作流快照，输出有序的加工目标计划。Avalonia 控件不直接拼装生成请求。

### Avalonia 画布

新增专用工作流画布替代现有只读 PMT 预览的主要交互职责。画布负责绘制和命中测试，不持有业务真相。所有编辑操作先转换为领域命令，校验后产生新工作流快照，再由画布重绘。

画布支持缩放、平移、适应全部和适应工件。参数节点通常位于工件外侧；PMT 和时间戳位于工件内部。连线允许跨越工件边界。

### Python 生成器

`laser_pmt.py` 的请求模型升级为显式目标计划，不再用参数列表的笛卡尔积推断 PMT 数量。生成器仍独立执行防御性校验，并负责：

- 读取和验证基础 machine 目录；
- 为 PMT 生成或复用 NPY 内容组；
- 为时间戳生成数字轮廓和水平填充 NPY；
- 生成独立 PMT JSON；
- 生成包含 PMT 和时间戳的 `allmachine.json`；
- 写出 CSV 和版本 2 布局；
- 完整包校验与原子发布。

## 节点和参数语义

### 基础参数节点

工作流中始终只有一个 `BaseParameterNode`。它默认包含基础 `machine.json` 第一组激光参数中的全部可编辑项，并作为整体连接到所有当前及以后创建的 PMT 和时间戳。

基础连接在模型中表示为系统级继承关系。界面用一条从基础节点到工件的总线表达，而不是为每个目标绘制一条线。目标入口显示已继承状态。

用户可以从基础节点移除参数项，也可以恢复它。移除表示该参数不再提供默认值；每个加工目标都必须通过单参数节点获得该参数，否则目标配置不完整并禁止生成。不得静默回退到基础 machine 的原值，也不得在生成 JSON 中省略控制器要求的字段。

### 单参数节点

每个 `SingleParameterNode` 只表示一个参数名，例如 `power`。值编辑框接受逗号分隔的显式值，例如 `20, 30, 40`。空项、重复值、非法整数、越界整数和非法布尔值均为错误。

每个值产生一个编号输出端。可见编号按当前列表顺序显示为 `1、2、3…`，端口和线段中部均显示该编号。连线持久化时使用稳定端口 ID，而不是可见编号或数组下标。

编辑值列表时，系统先按原位置和规范化后的原值匹配既有端口，尽量保留稳定 ID。没有匹配的值创建新端口；被删除值的端口及其连线被删除，并向用户提示受影响的目标。

同一端口可以连接多个 PMT 或时间戳。同一目标的同一参数最多接收一个单参数端口；尝试建立第二条连接时立即拒绝并高亮冲突入口。单参数连接覆盖基础节点中的同名值。

## PMT 生命周期和布局

PMT 总数量由独立的“PMT 数量”字段控制，“每行数量”仅用于初始自动排列及显式自动重排。初次创建时，PMT 按现有从左到右、从上到下的等间距规则放入工件。

“PMT 数量”始终显示当前实际存在的 PMT 数量。单独删除 PMT 后该字段同步减一；直接修改该字段则按下述增加或减少规则调整现有集合。

每个 PMT 可以单独拖动，也可以单独删除。PMT 尺寸继续来自基础加工几何，不允许单独缩放。

编号规则如下：

- 每个 PMT 获得稳定 ID 和基于现有前缀、起始值、步长、补零宽度生成的编号。
- 删除 PMT 时一并删除指向它的连线，但其他 PMT 不移动、不重新编号。
- 删除造成的编号空缺永久保留，不自动复用。
- 文档保存下一可用编号，新增 PMT 始终使用从未使用过的新编号。
- 增加 PMT 数量时，追加新编号并把新 PMT 放到首个满足边界和不重叠要求的自动布局位置；既有 PMT 的位置和连线不变。
- 减少 PMT 数量时，从当前编号最大的 PMT 开始删除，直到达到目标数量。

修改“每行数量”只影响以后新增且尚未手动移动的 PMT 候选位置，不移动已存在的 PMT。界面提供显式“自动重新排列”操作；执行前提示其会覆盖全部 PMT 的手动位置，但不会改变编号、参数或连线。

## 时间戳加工元素

用户可以添加任意数量的 `TimestampTarget`。每个时间戳创建时以当前本地时间的 `MMddHHmm` 作为默认文本，例如 `08310712`，之后保持固定。用户可以手动编辑，但最终值必须恰好是 8 位数字。

时间戳具有稳定 ID 和单调递增的创建序号，可以移动、缩放和删除。位置与尺寸使用工件物理坐标保存。缩放改变数字整体的物理宽度和高度，不改变文本内容。

生成器使用随应用发布的确定性数字字形轮廓。字形轮廓内部以水平方向扫描线填充，线间距始终沿用当前项目的 Hatch spacing，不提供单独设置。生成结果被转换为控制器兼容的 NPY；dtype、shape、有限值、坐标方向和引用方式遵循现有 patch 契约。完全相同的时间戳 NPY 内容组可以沿用现有逐数组精确比较机制复用。

时间戳与 PMT 使用相同的基础参数继承和单参数覆盖规则。它不生成独立机器 JSON，只出现在 `allmachine.json`、`pmt-layout.json` 和 `parameter-map.csv` 中。

## 加工顺序和输出

所有 PMT 先按编号从小到大加工；编号空缺不会生成占位任务。全部 PMT 完成后，时间戳按创建序号从小到大加工。画布位置不改变加工顺序。

每个 PMT 继续生成可独立运行的 `pmt_xxxxmachine.json`。独立文件使用该 PMT 的最终参数和本地运动语义，不包含时间戳。`allmachine.json` 根据每个元素的全局工件位置重新计算连续相对运动，依次包含全部 PMT 和时间戳。

`parameter-map.csv` 至少记录：

- 目标类型、稳定 ID、显示编号或时间戳文本；
- 加工顺序、物理位置和尺寸；
- 每个最终参数值及其来源节点、稳定端口 ID 和可见端口编号；
- JSON 文件名（时间戳为空）；
- NPY 内容组及 patch 引用。

## 交互设计

### 画布操作

- 空白区域拖动用于平移，滚轮用于缩放。
- 节点通过标题栏拖动。
- PMT 和时间戳在工件内直接拖动。
- 选中时间戳时显示四角缩放柄；右侧检查器中的宽高数值与拖动缩放双向同步。
- 从单参数节点的编号端口拖到目标参数入口建立连线。
- 点击线或端口后按 Delete 删除连接。
- 选中 PMT 或时间戳时，检查器显示基础值、覆盖值、连接来源和最终值。

拖动和缩放过程中允许元素暂时越界或重叠，以免打断编辑。无效元素和关联错误在画布上标红，生成操作保持禁用；松手后不自动弹回。

### 错误呈现

校验错误分为三层：

- 节点级：空值、重复值、类型错误和非法时间戳显示在节点内部。
- 连线级：端口类型不匹配或同目标同参数重复输入时拒绝连接，并短暂高亮目标入口。
- 工件级：缺失参数、元素越界或元素相交时目标标红。

顶部显示错误数量汇总。点击错误必须能够选择并定位对应节点、连线或目标。

## 几何约束

所有 PMT 和时间戳必须完整位于工件边界内。以下任意相交均为生成阻断错误：

- PMT 与 PMT；
- PMT 与时间戳；
- 时间戳与时间戳。

边界接触和元素边缘接触允许；只有正面积重叠才算相交。几何判断和生成前校验使用与机器坐标发射相同的精度规则，避免预览合法但舍入后越界或重叠。

## 验证、失败和兼容性

生成开始时重新读取基础目录并核对身份信息，然后重新编译版本 2 工作流。任何基础文件变化、编译错误、目标缺参、越界、相交或保存编译结果不一致都会阻止生成。

输出继续使用现有所有权锁、私有临时构建目录、完整重载验证和不覆盖式原子发布。失败或取消不得留下部分可见的正式输出；无法安全证明所有权的路径不得递归删除。

旧版 `pmt-layout.json` 可以只读打开。应用根据旧布局构造等价的基础参数节点和 PMT 目标用于预览。用户执行首次编辑时必须选择新输出位置并保存为版本 2，不原地修改历史生成目录。

- 基础参数删除、恢复和覆盖优先级。
- 缺失基础项时每个目标的补齐要求。
- 单参数值解析、稳定端口 ID、可见编号和失效连线清理。
- 一个端口连接多个目标以及重复目标参数连接拒绝。
- PMT 新增、最大编号删除、单独删除、编号空缺和编号不复用。
- PMT 手动位置在数量和每行数量变化后保持稳定。
- 显式自动重排不改变编号或连线。
- 三类元素相交和工件边界检测。
- 版本 2 工作流序列化往返与保存编译结果核对。

### Python 生成测试

- 显式目标计划解析与参数完整性。
- PMT 独立 JSON 和 `allmachine.json` 的参数、位置及 NPY 引用一致性。
- 合法 8 位时间戳和非法输入。
- 默认 `MMddHHmm` 在 C# 工作流层固定后被 Python 原样处理。
- 确定性数字轮廓、水平填充方向、Hatch spacing、缩放和坐标变换。
- 时间戳 NPY 的 dtype、shape、有限值及内容组复用。
- PMT 全部先于时间戳，时间戳按创建顺序执行。

- CSV、布局、JSON 和 NPY 的交叉验证。
- 冲突保护、取消、失败清理和原子发布。

### UI 和契约测试

- 缩放和平移后节点、端口、连线、编号标签和目标命中准确。
- PMT 可独立拖动、删除并保留编号空缺。
- 时间戳可添加多个、编辑、移动、缩放和删除。
- 错误汇总能够定位对应对象。
- 选中目标时显示基础值、覆盖来源和最终值。
- 旧格式保持只读，新格式编辑和恢复完整。

## 验收标准

1. 用户能在同一画布中完成基础继承、基础项删除、单参数多值分线和一个端口复用到多个目标。
2. 每条参数线显示与源端口一致的编号，并在保存、重开和画布变换后保持正确映射。
3. PMT 可自动创建、独立拖动和独立删除；删除后编号空缺、其他编号和连线保持不变。
4. 可添加多个时间戳，默认值、手动编辑、移动、缩放、水平填充 NPY 和加工参数均符合本设计。
5. 任意缺参、非法值、越界或正面积重叠都会明确标红并禁止生成。
6. 合法工作流生成的独立 PMT JSON、`allmachine.json`、NPY、CSV 和版本 2 布局能够通过完整包校验。
7. `allmachine.json` 始终先加工按编号排序的 PMT，再加工按创建顺序排序的时间戳。
8. 现有非 PMT 流程和旧 PMT 输出的只读预览不回归。
