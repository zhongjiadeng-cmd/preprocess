# “全部执行”上拉分割按钮设计

## 目标

把“三步流程”底部当前并列的“全部执行”和“单步执行”两个按钮合并为一个视觉统一的分割按钮：左侧主区域继续直接执行完整三步流程，右侧窄按钮向上展开三个单步执行入口。

## 交互设计

- 主区域文案保持“全部执行”，点击后立即调用现有 `PipelineRunMode.All` 流程。
- 右侧使用清晰的向上箭头，宽度明显小于主区域；点击只展开菜单，不直接执行任务。
- 菜单固定向按钮上方展开，依次显示“第 1 步：灰度分层”“第 2 步：生成 DXF”“第 3 步：生成加工文件”。
- 选择菜单项后立即关闭菜单，并调用对应的现有单步运行模式。
- 流程运行期间整个分割按钮不可用，防止重复启动；任务正常完成、失败或取消后统一恢复。

## 组件与样式

使用 Avalonia 11.3.18 提供的原生 `SplitButton` 作为语义控件，并为它增加与现有 `accent` 主按钮一致的主题样式。控件高度、字体、字重、蓝色背景以及悬停和按压反馈沿用 `UiTheme` 的设计令牌。

左右区域组成一个连续轮廓：左侧保留左圆角，右侧保留右圆角，中间只有轻量分隔线。右侧按钮保持足够的点击面积，但不与主操作争夺视觉权重。弹出内容沿用现有深色卡片与按钮风格。

## 代码边界

- `MainWindow` 负责创建分割按钮、连接完整流程及三个单步流程，并在运行生命周期内更新启用状态。
- `UiTheme` 负责分割按钮的统一视觉样式，不在业务代码中散落颜色或交互状态值。
- 现有 `RunPipelineAsync`、输入校验、进度窗口、取消行为和输出逻辑保持不变。
- 删除不再需要的独立“单步执行”按钮，但保留现有单步菜单项创建逻辑，按原模式调用。

## 错误处理

分割按钮只改变启动入口。所有参数错误、文件冲突、运行异常和取消处理继续由现有流程负责。无论流程以何种方式结束，按钮状态均通过现有 `try/finally` 生命周期恢复。

## 测试与验收

- 更新静态界面测试，确认存在“全部执行”分割按钮、向上菜单和三个明确的单步模式。
- 运行 Python 测试套件，确保三步流程契约未回归。
- 运行 .NET 测试与编译，确认 Avalonia 控件及主题样式有效。
- 视觉验收：主按钮与右侧箭头构成单一连续控件；菜单向上展开；悬停、按压、禁用状态与应用内其他主按钮一致。

## 非目标

- 不改变三个处理步骤的业务逻辑、顺序或依赖校验。
- 不记忆上一次单步选择，也不把某个单步提升为新的默认主操作。
- 不调整三步流程页面的其他布局或控件。
