# PMT Mode Extraction v2 Design

## Goal

Extract PMT generation from the pipeline's fourth step into an explicit PMT editing mode. The normal **Run All** action runs only grayscale layering, DXF generation, and machine-file generation. PMT editing is live and non-destructive: every edit updates an in-memory draft and the preview immediately, while only the explicit save action writes PMT output files.

The redesign starts from `main`. The previous `codex/pmt-mode-extraction` branch is retained only as a reference and is not used as the implementation base.

## Product Principles

1. PMT is a spatial editing mode, not pipeline step 4.
2. Editing feedback is immediate; disk output is explicit.
3. The canvas is the primary control surface.
4. Multiple source machine packages are first-class.
5. Preview geometry must use the same millimetre dimensions as generated machining geometry.
6. Existing node-based batch parameter editing remains available.
7. Controls favour compact icons, tooltips, keyboard access, and accessible names.

## Pipeline Boundary

- `Run All` always runs exactly three steps:
  1. grayscale layering;
  2. DXF generation;
  3. machine-file generation.
- The single-step menu exposes only those three steps.
- Step 3 may add its generated machine package to the PMT source catalogue, but it never creates, saves, or overwrites a PMT draft or PMT output.
- PMT generation is invoked only through the PMT save split button.
- Legacy strings and paths that refer to PMT as step 4 are removed from active UI and execution flow.

## Mode Layout

### Entering and leaving PMT mode

- Entering PMT mode immediately hides the right-hand three-step parameter inspector and expands the PMT canvas into the available width.
- Leaving PMT mode immediately restores the normal inspector.
- No translation, indentation, slide, or delayed spatial transition is used.
- Switching to texture or DXF preview, or leaving PMT mode, preserves the PMT draft without prompting.
- The PMT canvas continues to show the spatial workpiece, PMT targets, source base-parameter nodes, parameter nodes, and their connections.

### PMT toolbar

PMT mode adds compact controls to the internal window toolbar:

- **Grid icon + `PMT`**: opens the WPS-style matrix picker.
- **Source/import icon**: imports one or more source machine packages and selects the active source.
- **Source assignment icon/menu**: shows the source legend and assigns a source to selected PMTs.
- **Renumber icon**: explicitly renumbers PMTs by current spatial position.
- **Auto-arrange icon**: rearranges PMTs when requested; it is never triggered implicitly by deletion or source reassignment.
- **Save split button**: the main icon saves with the current draft name; the chevron menu contains `设置 PMT 加工文件名…`.

Except for the domain-specific `PMT` label, toolbar actions use icons rather than text labels. Every icon button has a tooltip, keyboard focus treatment, and an automation/accessibility name.

The icon language follows the compact 24×24 outline style demonstrated by [Morphicons](https://www.morphicons.com/): approximately 1.5–2 px strokes, restrained detail, and consistent optical sizing. Morphicons is a web morphing library rather than an icon set, so the desktop app does not add its JavaScript runtime. The existing `UiIcons` system is extended with compatible static vector paths. Relevant upstream licences are preserved when source paths are adapted (Morphicons MIT; Lucide ISC; Heroicons and Tabler MIT).

## Matrix Creation

The `[PMT]` control opens a light popover modelled on WPS table creation:

- A grid cell under the pointer highlights a complete rectangle from the top-left cell to the pointer.
- The header reports `R 行 × C 列 · N 个 PMT`.
- Hovering produces an ephemeral canvas preview without dirtying the draft.
- Clicking a grid cell creates the complete `R × C` matrix in the in-memory draft and marks it dirty.
- There is no `确定` or `应用` button.
- Closing the popover without clicking discards only the hover preview.
- New matrix cells use the currently active source package.
- Default numbering is left to right, top to bottom, starting at 1.

Users may delete surplus PMTs after creating a complete rectangle. Deletion leaves a spatial hole; it does not move or renumber remaining PMTs. Renumbering is always an explicit command.

## Source Machine Packages

### Import and catalogue

A `PmtSourceCatalog` owns all source packages in the draft. Sources may come from:

- the machine package generated by pipeline step 3; or
- one or more machine-package directories selected through the PMT source importer.

Each source record contains:

- a stable source ID;
- directory and display name;
- a fingerprint of `machine.json` and required patch files;
- native design width and height computed from the machine file;
- base machining parameters;
- a stable high-contrast colour and short visible mark.

Batch import accepts valid packages and reports invalid packages together with their individual reasons. A missing or externally changed source remains in the draft but is visibly marked and blocks saving until the user relocates or reloads it.

### Source assignment

- A new matrix uses the active source for every cell.
- `Command`-click supports multi-selection of PMTs.
- The source menu assigns another imported source to all selected PMTs.
- Reassignment preserves each PMT centre.
- A locked PMT adopts the newly assigned source's native width and height.
- If the new dimensions overlap another target or exceed the workpiece, the affected targets are marked invalid; nothing is silently moved.
- The user may move targets manually or invoke explicit auto-arrange.

### Visible differentiation

PMTs from different sources are distinguished with all three of:

- a stable high-contrast border colour;
- a short corner mark;
- the source display name in selection details and tooltips.

The design must not rely on colour alone. A toolbar legend maps every source mark and colour to its display name.

## True-Scale Geometry and Size Locking

The entire workpiece and every PMT use a shared millimetre coordinate system. A source whose design size is 40 × 20 mm must render at exactly twice the width of a 20 × 20 mm source at the same zoom.

Each PMT stores:

- native source width and height;
- current width and height;
- centre/position;
- size-lock state.

New targets are locked to native size. In the selected-PMT popover:

- a lock icon communicates and toggles the state;
- locked width and height are read-only;
- unlocked width and height are independently editable;
- edits immediately change the draft, canvas, validation, and dirty state;
- generation scales all source machining coordinates by the corresponding X and Y ratios, so output geometry matches the preview rather than merely resizing the outline;
- locking an unlocked target asks whether to restore native dimensions or freeze the current custom dimensions.

## Workpiece and Target Editing

### Workpiece popover

Clicking the workpiece border opens a nearby lightweight popover. Width and height edits update the draft and canvas on every valid value change. There is no apply button; closing the popover retains the draft values.

### Selected-PMT popover

Clicking one PMT opens a nearby popover with:

- **Geometry**: number, X, Y, width, height, and the size lock.
- **Final parameters**: every effective machining parameter for that PMT.

Final parameters are resolved in this order:

1. source package base value;
2. connected batch parameter node value;
3. direct per-PMT override.

Editing a final parameter immediately creates or updates the direct override. Each direct override has `恢复继承值`, which removes it and reveals the batch-node or source value beneath it.

The popover does not contain a delete button. Target deletion is a keyboard action.

## Node-Based Batch Parameter Editing

The existing node-workflow interaction remains visible on the PMT canvas: base nodes, parameter nodes, ports, targets, and connections.

Each imported source owns one base-parameter node, identified with the same colour, short mark, and display name as its PMTs. This makes different source defaults visible without pretending that a multi-source draft has one shared base value.

A user can add a parameter unit node, select a machining parameter and value, then connect or apply it to multiple selected PMTs. Editing the node updates all connected targets immediately in the draft and their resolved final-parameter views.

Rules:

- A PMT may have at most one connected batch node for a given parameter.
- Applying another node for the same parameter replaces the previous batch connection rather than creating ambiguous inputs.
- A direct per-PMT override takes precedence over the batch node.
- Removing a direct override reveals the connected batch-node value.
- Removing a batch connection reveals the source base value unless a direct override exists.

## Keyboard Interaction

Canvas shortcuts apply only when the canvas owns keyboard focus. Text boxes, number fields, menus, and popovers retain normal editing behaviour.

- `Arrow keys`: select the nearest PMT in that spatial direction; skip deleted holes.
- `Command + Arrow`: move selected PMTs by 0.1 mm.
- `Shift + Command + Arrow`: move selected PMTs by 1 mm.
- `Delete` or `Backspace`: delete selected PMTs.
- `Command`-click: add/remove PMTs from the current multi-selection.

Directional navigation uses target centres. Candidates must lie in the requested half-plane; alignment with the requested axis is preferred, then distance. Custom movement therefore remains navigable without relying on creation order.

Every keyboard edit updates geometry validation and the dirty indicator immediately.

## Draft Model

`PmtDraftSession` is the single authoritative editing state. It contains:

- the workpiece and viewport;
- `PmtSourceCatalog`;
- PMT targets, timestamps, base nodes, parameter nodes, ports, and connections;
- per-target source IDs, geometry, size locks, and direct overrides;
- output name;
- current selection;
- validation results;
- a saved revision and current revision.

UI components never retain independent authoritative copies of counts, rows, sizes, parameter values, or dirty state. They dispatch draft commands and render the resulting immutable snapshot.

Required draft commands include:

- preview/commit matrix;
- resize workpiece;
- import/reload/relocate source;
- assign source;
- select and multi-select;
- edit geometry and nudge;
- lock/unlock size;
- delete targets;
- renumber by position;
- auto-arrange;
- add/edit/remove batch parameter nodes and connections;
- set/remove direct parameter overrides;
- set output name.

Every committed command increments the current revision and publishes one change notification. Hover-only matrix previews are transient and do not increment the revision.

## Dirty State and Destructive Transitions

- Switching PMT/texture/DXF views or leaving PMT mode preserves the draft without prompting.
- Closing the window, replacing the source set, or creating a new matrix when it would replace edited content prompts `保存 / 放弃 / 取消`.
- Save success sets the saved revision to the current revision.
- Save failure leaves the draft and both revision values unchanged.
- The toolbar shows unsaved state and the current validation-error count without modal interruption.

## Save Split Button

- Main action: validate and save using the current output name.
- Chevron menu: `设置 PMT 加工文件名…` opens a lightweight name editor.
- Name edits update only the in-memory draft.
- Invalid path characters, `.`/`..`, empty resolved names, and output collisions are reported immediately.
- Existing output is never silently overwritten.

`PmtSaveService` is the only component permitted to write PMT output. It:

1. snapshots the current draft revision;
2. validates geometry, sources, numbering, parameters, source fingerprints, and output paths;
3. writes a versioned multi-source request;
4. generates into a uniquely owned temporary directory;
5. verifies every generated per-PMT file, patch reference, layout record, and combined file;
6. atomically promotes the completed output;
7. marks the exact saved revision only if the draft has not changed underneath it.

If editing continues during a save, the completed revision is recorded, but later edits remain dirty.

## Multi-Source Generation Format

The PMT request format is upgraded to a version that contains:

- a source table keyed by source ID, with source directory, fingerprint, native dimensions, and base parameters;
- a target list in which each PMT references a source ID and contains bounds, X/Y scale, number, batch-resolved parameters, and direct overrides;
- workpiece, output name, owner token, and workflow metadata.

The Python generator loads and validates every referenced source independently. For each PMT it transforms the source's machining coordinates using that target's translation and X/Y scale, applies the resolved parameters, and writes an independent machine file. It then builds a combined `allmachine.json` in processing order.

Identical patch groups may be reused across targets and sources only when their generated contents are byte-equivalent. Source IDs alone are never considered sufficient proof of equivalence.

## Validation and Error Presentation

Live editing does not use blocking error dialogs. Invalid targets receive a prominent outline and error badge; the toolbar exposes the total error count and details.

Saving is blocked by:

- missing or changed sources;
- invalid source packages;
- non-finite or non-positive dimensions;
- targets outside the workpiece;
- target overlap;
- duplicate or invalid PMT numbers;
- invalid parameter values or ambiguous parameter inputs;
- invalid scaling output;
- invalid output names or path collisions.

Correcting a value clears its corresponding error immediately. A failed save never reloads or discards the draft. Temporary output is not presented as a successful result.

## Component Boundaries

- `PmtDraftSession`: commands, revisions, selection, validation, snapshots.
- `PmtSourceCatalog`: source import, metadata, fingerprints, marks, relocation.
- `PmtModeController`: mode entry/exit, destructive-transition prompts, UI composition.
- `PmtMatrixPopover`: WPS-style hover preview and matrix commit.
- `PmtWorkpiecePopover`: live workpiece editing.
- `PmtTargetPopover`: geometry, lock, final parameters, inherited-value restoration.
- `PmtSourceMenu`: active source, legend, import, multi-target assignment.
- `PmtWorkflowCanvas`: true-scale spatial rendering, nodes, connections, selection, keyboard navigation.
- `PmtSaveService`: exclusive disk-output boundary and atomic save orchestration.
- Python generator: multi-source validation, coordinate transformation, per-target and combined output.

`MainWindow` wires these components but does not implement their domain rules.

## Testing

### Draft and domain tests

- Complete matrix creation and transient hover preview.
- Default numbering; deletion leaves holes; explicit renumber orders left-to-right and top-to-bottom.
- Single and multi-selection, directional selection, 0.1 mm and 1 mm nudging.
- Shortcut suppression while an editor owns focus.
- Source import, assignment, relocation, and changed-source detection.
- Native-size locking, independent X/Y scaling, both relock choices.
- Base → batch node → direct override resolution and restoration.
- Revision and dirty-state transitions, including edits during save.

### Geometry tests

- Different sources render at their exact relative millimetre dimensions.
- Source reassignment preserves centres.
- Overlap/out-of-bounds validation after reassignment and scaling.
- Auto-arrange respects each target's actual dimensions.
- Directional navigation after deletion and arbitrary movement.

### Generator tests

- Multi-source request parsing and source fingerprint validation.
- Correct source binding per PMT.
- Translation and independent X/Y coordinate scaling.
- Batch and direct parameter resolution.
- Safe patch reuse by generated-content equality.
- Per-PMT outputs, layout metadata, and combined `allmachine.json`.
- Collision rejection, temporary-output cleanup semantics, and atomic promotion.

### UI and regression tests

- `Run All` and the step menu contain only three pipeline steps.
- PMT mode changes layout without a spatial transition.
- Live editing causes no PMT disk writes.
- The save service is the only PMT output writer.
- Save split-button naming behaviour.
- Tooltips, automation names, focus visuals, and keyboard access for icon buttons.
- Source differentiation remains understandable without colour.
- Dark and light theme rendering.

### Manual visual QA

At minimum, exercise:

- two or more source packages with visibly different native dimensions;
- a complete matrix with deleted holes;
- multi-select source reassignment;
- node-based batch parameter editing and direct override precedence;
- locked, unlocked, non-uniformly scaled, and relocked targets;
- keyboard selection, nudging, and deletion;
- invalid overlap/out-of-bounds states;
- save failure followed by correction and successful retry.

## Out of Scope

- A general undo/redo command history.
- Silent overwrite of existing PMT output.
- Automatic PMT generation after pipeline step 3.
- Importing arbitrary standalone JSON files that are not valid machine packages with their required patches.
- Adding the Morphicons web runtime or decorative icon-morph animations.

## Acceptance Summary

The feature is complete when PMT is no longer pipeline step 4; PMT mode has an immediate full-width canvas; multiple true-scale sources can be imported, assigned, distinguished, parameterised, and scaled; spatial and node-based editing update one in-memory draft in real time; keyboard operations work without breaking editors; and only the explicit save split button produces validated PMT output.
