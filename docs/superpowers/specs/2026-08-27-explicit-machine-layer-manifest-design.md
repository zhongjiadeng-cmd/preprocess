# 加工文件显式层清单设计

## 背景

主流程允许重复使用 TIFF 与 DXF 输出目录。分层数量变化时，文件名的补零宽度也会变化：单层运行生成 `layer_1_...dxf`，十层运行生成 `layer_01_...dxf`。历史文件不会被覆盖或删除，因此两个名称可能在同一目录中并存，并被加工文件脚本解析为重复的数字层号。

当前 C# 主流程虽然维护了本次生成的 DXF 清单，但第三步只把目录传给 Python。Python 随后重新扫描整个目录，使已经验证的本次清单在组件边界丢失，历史 DXF 仍可能进入加工输入。

## 目标

- 主流程生成加工文件时，只消费本次第二步成功生成并验证的 DXF。
- 保留输出目录中的历史文件，不覆盖、不修改、不删除它们。
- 保持 `dxf_to_machine_file.py <dxf_dir> [output_name]` 的现有命令行和 Python API 行为兼容。
- 显式清单无效时，在创建加工文件输出前失败并给出可定位的错误。

## 非目标

- 不改变 TIFF、DXF、分块元数据或机器加工文件的格式。
- 不改变独立调用加工文件脚本时默认扫描目录的行为。
- 不自动清理或迁移历史输出文件。
- 不改变层号命名或补零规则。

## 方案

### Python 接口

为加工文件生成链增加可选的显式层文件清单：

```python
generate_machine_file(
    dxf_dir: Path,
    output_name: str | None,
    layer_step_um: float,
    first_laser_params: dict[str, object],
    *,
    owner_token: str | None = None,
    block_center_positioning: bool = False,
    layer_files: list[Path] | None = None,
) -> Path
```

命令行增加可重复参数：

```text
--layer-dxf /absolute/path/layer_01_gray_lt_255.dxf
```

未提供 `layer_files`/`--layer-dxf` 时，继续调用 `discover_layer_dxf_files(dxf_dir)`，保持当前行为。提供清单时，不再发现目录中的其他 DXF；先对清单进行校验、按数字层号排序，再把结果传给已有 patch 规划与生成逻辑。

显式清单校验规则：

1. 清单不能为空。
2. 每个路径必须是绝对路径，规范化后必须是 `dxf_dir` 的直接子文件，不能来自子目录或其他目录。
3. 文件名必须符合现有 `layer_<正整数>_*.dxf` 规则，且必须是普通文件。
4. 数字层号必须唯一并连续。
5. 排序依据是数字层号，不依赖调用方传入顺序。

校验完成前不得创建最终目录、临时构建目录或锁文件。显式文件在后续读取或生成期间发生替换、删除等情况时，沿用现有文件读取与原子发布失败处理。

### C# 主流程

第二步已有 `currentRunDxfFiles`，并且每个文件在加入清单前已通过产物校验。启动第三步时，为清单中的每个路径追加一组 `--layer-dxf` 与绝对路径参数。

目录清单检查继续保留，作为面向用户的诊断信息和缺失文件检查；但历史 `layer_*.dxf` 不再被视为错误。检查只验证本次预期路径仍是非空普通文件，并记录本次清单数量。这样重复使用目录可以正常工作，同时第三步的实际输入由显式清单强制约束。

主流程不删除意外文件，也不把历史 DXF 加入预览或加工文件。

## 数据流

```text
本次 TIFF 清单
    → 逐层生成并验证 DXF
    → currentRunDxfFiles（绝对路径）
    → --layer-dxf 参数
    → Python 校验并排序显式清单
    → patch 计划
    → 原子发布机器加工文件
```

目录扫描只保留给未传显式清单的独立 Python 调用，不再是主流程第三步的数据来源。

## 错误处理

- 清单为空、路径非绝对、越出指定目录、不是直接子文件、名称无效、文件缺失、层号重复或不连续时，Python 返回非零退出码并说明具体问题。
- 主流程在启动 Python 前仍复查每个本次 DXF 是非空普通文件，以便提供更接近用户操作的错误。
- 历史 DXF、预览 PNG 和分块 JSON 可以留在目录中，不触发清单不一致错误。
- 不放宽显式清单自身的重复层号检查；只有未列入清单的历史文件会被忽略。

## 测试

Python 行为测试：

- 目录同时包含 `layer_1_old.dxf` 与 `layer_01_current.dxf`，显式清单只包含 current 文件时，成功生成一层加工文件。
- 显式清单顺序打乱时，仍按数字层号生成。
- 清单自身包含重复数字层号、层号间断、相对路径、目录外路径、子目录路径、缺失文件或无效名称时，在发布输出前失败。
- 未提供显式清单时，目录中的重复数字层号仍按现有规则失败，证明向后兼容。
- CLI 可重复 `--layer-dxf` 参数只加工列出的文件，并正确报告层数。

C# 源码契约测试：

- 第三步为 `currentRunDxfFiles` 中每个绝对路径追加 `--layer-dxf` 参数。
- 主流程复查预期文件，但不再因未列入本次清单的历史 DXF 失败。
