# 末条加工周期重新声明 G91 设计

## 背景

现有加工文件仅在第一条 `machine_cycle` 指令前写入 `G91`，并在最后一条指令末尾追加 `G90`。实机加工表明，最后一块关联的 XY 相对移动可能未在 patch 加工前生效；末块会停留在上一块中心重复加工。

## 目标

最后一条加工周期必须在运动指令前重新声明相对坐标模式，同时保留运动后的 `G90` 恢复：

```gcode
G91G00X...Y...Z...F40G90
```

此变更只调整末条指令的模式声明，不改变块中心、相对位移、patch 编号、patch 内容或最终 `G90`。

## 指令格式

- 多块任务第一条：`G91G00...F40`
- 多块任务中间条目：`G00...F40`
- 多块任务最后一条：`G91G00...F40G90`
- 单块任务：`G91G00...F40G90`

末条中的 X、Y、Z 继续表示当前块目标位置减上一已命令位置所得的相对增量。

## 生成与校验

`build_machine_document` 在第一条和最后一条指令前添加 `G91`。单块任务的同一条指令只添加一次。

严格控制器模拟器必须接受并要求末条的 `G91`，在解析末条运动前把模式重新设为相对模式；运动在 `F40` 时完成，随后解析尾部 `G90` 并恢复绝对模式。非末条出现额外 `G91` 或末条缺少 `G91` 均视为格式错误。

## 现有加工文件

不修改工作区内已经生成的任何 `machine.json` 或 patch 文件。修复仅作用于修改代码后新生成的加工文件。

## 测试与验收

- 先添加一个多块回归测试，证明旧生成器产生的末条缺少 `G91`。
- 更新单块、多块、分层及严格解析相关断言。
- 运行完整 Python 单元测试。
- 通过临时测试输出检查：只有第一条和最后一条以 `G91` 开头，单块情况下同一条只出现一次。
- 构建 macOS 应用，确认调用接口未受影响。

本地自动化验证只能证明文件格式和计算契约正确；最终实机验证以末块回到右下目标区域且不再在上一块中心重复加工为准。
