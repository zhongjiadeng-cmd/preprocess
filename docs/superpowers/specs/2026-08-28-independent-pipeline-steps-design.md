# 主流程三步骤独立执行设计

## 目标

在现有“灰度分层 → Hatch DXF → 加工文件”主流程页面中，为三个步骤分别提供独立启动入口，同时保留原有“一次执行三步”的按钮和行为。用户可以先执行灰度分层检查 TIFF 结果，确认后再执行 DXF 生成，最后再生成机器加工文件。

## 用户交互

主流程页面继续保留“开始三步处理”，并在同一操作区增加三个按钮：

- “仅执行第 1 步：灰度分层”
- “仅执行第 2 步：生成 DXF”
- “仅执行第 3 步：生成加工文件”

单步按钮只执行对应步骤，不隐式执行前置步骤：

1. 第 1 步读取原始灰度图，按当前分层参数生成分层 TIFF。
2. 第 2 步读取分层 TIFF 输出目录中已有的 `layer_*.tiff`，按当前 Hatch/DXF 参数逐层生成 DXF 与 `.preview.png`。
3. 第 3 步读取 DXF 输出目录中已有的 DXF 文件，按当前机器参数生成加工文件。

单步执行前校验所需输入和产物：原始图片、输出目录、有效的分层 TIFF 或有效的 DXF 清单。缺失或无效时显示明确错误，不启动 Python 进程。

## 实现结构

将现有 `RunPipelineAsync` 中的三个执行阶段拆为可复用的步骤方法，并保留共同的取消、日志、进度和异常处理框架：

- 第 1 步方法负责 Python 分层命令、参数构造、生成数量校验和日志。
- 第 2 步方法负责发现并排序已有 TIFF、逐层调用 Hatch 脚本、验证 DXF/预览/配准信息，并更新 DXF 层选择器。
- 第 3 步方法负责校验本次输入 DXF 清单、构造机器文件命令、检查输出目录和冲突路径。
- 三步入口按顺序调用三个方法；单步入口只调用目标方法。

三步入口继续使用原有“步骤 1/3、步骤 2/3、步骤 3/3”日志语义。单步入口使用对应步骤名称，并在成功后报告生成数量或加工文件路径。

## 状态与按钮

运行期间保留当前取消机制，防止同时启动多个流程。主流程的四个启动按钮在任一主流程运行时禁用，取消按钮启用；运行结束后恢复按钮状态。第 3 步成功生成的加工文件继续启用“打开加工文件目录”。第 2 步成功生成的 DXF 继续逐项加入层选择器并可预览。

为避免无关参数被错误修改，运行期间继续禁用与当前流程相关的分块参数；单步执行时也遵循同样的禁用与恢复规则。现有独立“灰度图分层”和“Texture to Hatch”页面不改变。

## 输出与安全规则

第 1、2 步沿用现有输出目录和文件校验规则。第 3 步沿用现有加工文件名、临时目录、锁文件冲突检查，以及取消/失败时保留残留路径并记录日志的规则。单步第 3 步的 DXF 清单以执行时扫描到的有效 `*.dxf` 为准，并作为本次机器文件调用的显式输入。

## 测试与验收

增加或调整源码结构测试，确认：

- 四个启动入口都存在，三步按钮仍调用完整流程。
- 单步第 1 步不会调用 Hatch 或机器文件脚本。
- 单步第 2 步使用已有 `layer_*.tiff`，不会重新生成 TIFF。
- 单步第 3 步使用已有 DXF，不会调用前两步脚本。
- 缺少单步所需输入时不会启动进程并返回清晰提示。
- 现有取消、日志、DXF 预览加入和加工文件路径检查继续有效。

验收标准是：用户可分别启动任一步骤并检查中间结果；原“开始三步处理”仍能按原顺序一次完成全部输出；单步执行不会覆盖或删除不在本次输入清单中的已有结果。
