# 顶部导入进度 Reverse Collapse 浮层设计

## 背景

顶部“导入中间结果”支持导入分层 TIFF、DXF 或两者的混合文件，但当前只在页面底部显示不确定进度条。用户无法判断应用正在扫描、校验还是加载预览，也看不到已处理文件数量。

本设计仅增强顶部“导入中间结果”的反馈。原始灰度图选择、目录字段选择、“全部执行”和单步执行不纳入范围，现有导入结果、预览切换和冲突操作禁用规则保持不变。

## 目标

- 从顶部“导入”按钮下方反向展开一个非模态进度浮层。
- 持续显示导入阶段、当前文件、已处理数量和总体进度。
- 成功后提供短暂而明确的完成反馈，再沿原路径收拢。
- 失败时保留浮层并显示可操作的错误信息，不提交部分结果。
- 尊重系统“减少动态效果”偏好，并保持深色与浅色主题一致。

## 不在本次范围

- 不改变顶部导入菜单、文件选择器或支持的文件类型。
- 不为“选择图片”等其他导入入口增加进度浮层。
- 不增加取消导入功能。
- 不改变“全部执行”已有的独立进度窗口。
- 不增加导入队列、历史记录、后台通知或并行解析。
- 不重排主窗口结构，也不推动预览区或参数区布局。

## 交互与视觉

用户从顶部“导入”菜单完成文件或文件夹选择后，进度浮层以“导入”按钮为锚点，从按钮下边缘向下展开。浮层悬浮在主内容之上，不移动现有布局，不阻断预览区查看。

浮层目标宽度约为 320 px，采用现有主题的卡片背景、边框、圆角、文字层级与图标体系。内容从上到下为：

1. 导入图标与阶段标题。
2. 当前文件名或当前操作说明，使用单行截断并提供完整 Tooltip。
3. 进度条。
4. 数量摘要，例如“正在检查分层 TIFF · 4/10”。

扫描阶段尚不知道总数时显示不确定进度。完成文件发现后切换为确定进度；TIFF 与 DXF 混合导入共用一个总文件数，切换文件类型时不归零。

导入期间继续禁用“导入”“清空缓存”和“全部执行”，沿用现有防冲突逻辑。浮层本身非模态，不获取不必要的键盘焦点。

### Reverse Collapse 动画

- 展开：从锚点下方的折叠高度开始，约 280 ms 内展开至内容高度，同时由低透明度渐显。
- 收拢：成功反馈结束后使用对称路径向“导入”按钮收拢，同时渐隐。
- 动画无回弹，采用接近临界阻尼的平稳响应，避免工具型桌面应用出现夸张弹跳。
- 当目标状态在动画途中改变时，从当前呈现值继续，不跳回起点；成功状态可以反向接管仍在进行的展开动画。
- 窗口移动或缩放时，浮层重新依据“导入”按钮定位，不固定到屏幕绝对坐标。
- 开启“减少动态效果”时取消高度与位移动画，只保留短时交叉淡入淡出；信息反馈不被移除。

## 状态与数据模型

新增轻量的 `ImportProgressState`，仅表达界面所需状态：

- `Stage`：扫描、校验 TIFF、校验 DXF、加载预览、成功或失败。
- `Current`：当前已处理文件数。
- `Total`：发现后的总文件数；扫描阶段可为空。
- `CurrentFileName`：当前文件名；无文件时为空。
- `Message`：阶段说明、成功摘要或失败原因。
- `IsTerminal` 与 `IsError`：决定完成收拢或错误停留。

状态是不可变快照。导入逻辑通过进度报告器向 UI 发布快照，`ImportProgressOverlay` 只渲染状态，不读取文件、不解析 TIFF/DXF，也不决定是否提交导入结果。

## 组件边界

### `ImportProgressOverlay`

负责浮层内容、主题、锚定、展开/收拢动画、减少动态效果分支以及失败状态的“关闭”按钮。它公开显示、更新、成功收拢和失败停留等小型接口，不持有导入业务状态。

### `ImportProgressState`

作为导入流程与浮层之间的稳定契约。阶段标题、计数文本和无障碍说明由集中格式化逻辑生成，避免两个导入入口产生不同文案。

### `MainWindow` 导入协调

顶部文件夹与多文件导入继续沿用现有入口。协调层在系统文件选择完成且用户确实选择内容后显示浮层，并把进度报告器传入文件发现、TIFF 校验、DXF 校验和预览加载过程。

现有文件选择、日志写入、目录字段更新、预览切换与最终状态提交顺序保持不变。

为兑现“失败不提交部分结果”，混合批次必须先完成全部 TIFF 与 DXF 校验，再开始更新任何路径字段、图层集合或预览。提交阶段仍沿用现有控制器接口，但由协调层统一安排在所有校验通过之后；如果加载预览本身失败，则恢复本批次开始前的界面快照。

## 导入数据流

1. 用户从顶部导入菜单选择“导入文件夹”或“导入文件”。
2. 系统选择器完成；用户取消时不显示进度浮层。
3. 显示浮层并报告“正在扫描文件”。
4. 文件发现完成后确定总文件数，并保存当前导入界面的可恢复快照。
5. 校验每个 TIFF 时更新文件名和累计数量，但不提交界面状态。
6. 校验每个 DXF 时继续使用同一累计数量，仍不提交界面状态。
7. 全部校验通过后，加载缩略图、预览和图层列表，并报告“正在加载预览”。
8. 加载成功后一次性更新路径字段、选择状态和日志；加载失败则恢复步骤 4 的快照。
9. 所有状态成功提交后显示完成摘要，例如“已导入 10 个文件”。
10. 完成状态停留约 0.6 秒，浮层沿展开路径反向收拢并关闭。

进度更新在 UI 调度器上串行应用，并按界面帧自然合并高频更新。不得为展示动画给文件处理增加人为延迟；0.6 秒只属于最终完成反馈。

## 失败与恢复

扫描、校验或加载任一阶段失败时：

- 不提交该批次的部分导入结果。
- 保留此前成功导入的预览和路径状态。
- 浮层保持展开，显示失败阶段、文件名与具体原因。
- 进度条切换为错误状态，显示“关闭”按钮。
- 用户关闭后，浮层沿原路径收拢。
- 日志仍记录完整错误信息。

顶部导入触发的可预期文件错误由浮层承载，不再额外叠加同内容的模态消息框。系统级选择器错误或无法恢复的窗口错误仍可使用现有消息框。

## 无障碍

- 浮层使用状态语义，并在阶段或计数发生有意义变化时更新无障碍名称。
- 不逐文件强制抢占 VoiceOver；播报节流到阶段变化和最终状态。
- 失败状态的“关闭”按钮可通过键盘访问，焦点仅在失败需要用户处理时移入浮层。
- 进度不能只靠颜色表达；始终同时显示文字和数量。
- 深色、浅色和高对比度下使用现有语义颜色令牌。

## 测试与验收

### 单元与契约测试

- 状态模型覆盖扫描、两类校验、加载、成功和失败转换。
- 文件夹、多个文件及 TIFF/DXF 混合导入持续报告进度，累计数量单调增加且不因类型切换归零。
- 损坏 TIFF、损坏 DXF 和加载失败均包含文件名与原因，不提交部分结果。
- 用户取消系统选择器时不显示浮层。
- 正常模式安装高度、位移与透明度过渡；减少动态效果模式不安装空间过渡。
- 完成状态触发延迟收拢，失败状态保持展开直到用户关闭。

### 回归测试

- 现有导入结果、日志、目录字段和预览选择测试保持通过。
- “全部执行”仍使用现有 `ProcessingProgressWindow`。
- 完整 .NET 与 Python 测试套件通过。

### 视觉验收

- 浮层从顶部“导入”按钮下方展开，并始终与按钮对齐。
- 浮层不推动主布局，不遮挡顶部按钮，不超出窗口边缘。
- 深色和浅色模式均有清晰边界与足够文字对比度。
- 长中文文件名和长英文路径不会撑破浮层。
- 成功后停留约 0.6 秒并沿原路径收拢；失败时稳定停留。
- 窗口缩放和移动后锚点位置正确。
- 减少动态效果模式只使用短暂淡入淡出。

## 完成标准

顶部“导入中间结果”的文件与文件夹导入均显示锚定式 Reverse Collapse 进度浮层，进度、成功与失败状态准确，原有导入操作和结果不变，所有自动化测试与 macOS 应用包视觉检查通过。
