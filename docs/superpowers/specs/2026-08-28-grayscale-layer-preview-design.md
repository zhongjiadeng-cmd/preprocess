# 灰度分层结果逐层预览设计

## 目标

在主流程的第 1 步“灰度分层”完成后，让用户可以直接检查每一层生成的 TIFF 效果，并在同一预览区域内放大、缩小和查看细节。该功能只扩展主流程的中间结果检查能力，不改变灰度分层算法、输出命名规则或第 2 步读取 TIFF 的行为。

## 用户交互

主流程预览区由现有“纹理”“DXF”两个标签扩展为三个标签：

- “分层”：展示第 1 步生成的 `layer_*.tiff`。
- “纹理”：保留当前原始纹理预览。
- “DXF”：保留当前 DXF/配准纹理预览。

选择“分层”后，预览区显示分层文件列表和主画布。文件列表按现有分层文件名排序，包含层序号、文件名和缩略图；默认选中第 1 层。点击任意缩略图后，主画布切换到对应 TIFF。

主画布提供“适应窗口”“放大”“缩小”“100%”操作。鼠标滚轮执行以光标位置为中心的缩放，拖动画布可平移。缩放比例限制在合理范围内，避免无限放大或缩小；切换图层时保留当前缩放状态，点击“适应窗口”重新计算适配比例。

第 1 步成功后自动刷新分层文件列表并切换到“分层”标签；如果输出目录为空、文件读取失败或没有有效的 `layer_*.tiff`，显示明确状态信息，其他两个标签仍可使用。重新执行第 1 步时先释放旧 TIFF 位图，再加载新列表。

## 实现结构

新增独立的分层预览状态和视图构造逻辑，与现有 `TexturePreviewController`、`DxfPreviewControl` 分开：

- `GrayscaleLayerPreviewItem`：保存 TIFF 路径、显示名称和可释放的缩略图/主图资源引用。
- `GrayscaleLayerPreviewController`：负责扫描、排序、选择图层、加载位图、处理失败状态和释放旧资源。
- `MainWindow`：持有分层预览列表与主画布，在第 1 步成功后调用刷新入口，并将“分层”标签接入现有共享预览布局。
- 缩放画布使用可滚动容器和统一的缩放变换；缩放操作只作用于分层主画布，不改变现有 DXF 预览交互。

分层扫描使用输出目录中匹配 `layer_*.tiff` 的文件，并使用稳定的序号/文件名排序。每次刷新形成新的条目集合；旧条目及其位图在替换前释放。选择条目时仅加载当前主图，缩略图加载失败不应阻塞其他层选择，但需在该条目上显示失败状态。

## 数据流

```text
第 1 步完成
  -> 校验输出目录
  -> 扫描 layer_*.tiff
  -> 排序并生成缩略图列表
  -> 默认选择第 1 层
  -> 加载主预览图
  -> 显示分层标签
```

第 2 步继续直接扫描同一分层 TIFF 输出目录，不依赖分层预览控件中的当前选择，也不读取预览缓存。预览只消费已生成文件，不参与 Python 命令参数构造或输出文件写入。

## 错误处理与资源

- 输出目录不存在或不可读：清空列表并显示“无法读取分层输出目录”及原因。
- 没有匹配文件：显示“尚未生成分层 TIFF”。
- 单个 TIFF 无法读取：保留条目并标记“无法预览”，允许继续选择其他层。
- 主窗口关闭、刷新列表或替换当前图层时，释放由预览控制器拥有的位图资源。
- 所有 UI 更新在 Avalonia UI 线程执行；文件扫描和位图读取不得阻塞运行日志与取消按钮。

## 测试与验收

增加单元测试覆盖：

- `layer_*.tiff` 的匹配、稳定排序和层名称提取。
- 空目录、无效目录和单文件读取失败时的状态结果。
- 切换图层后当前选择正确，刷新后默认选择第 1 层。
- 缩放控制的边界、适应窗口和 100% 状态。
- 刷新/关闭时旧预览资源被释放。

增加源码结构或 UI 行为测试确认：

- 主流程存在“分层”预览标签和缩略图列表。
- 第 1 步成功后触发分层预览刷新。
- 第 2 步仍从输出目录读取 `layer_*.tiff`，不依赖预览选择。
- 现有“纹理”“DXF”标签和 DXF 选择器行为保持有效。

验收标准：用户单步执行第 1 步后可以看到每层缩略图，点击任一层即可查看对应效果图，并可用按钮或滚轮放大缩小、适应窗口和恢复 100% 比例；执行后续步骤的输入输出行为不变。
