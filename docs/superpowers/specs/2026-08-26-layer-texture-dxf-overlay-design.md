# 灰度分层纹理与 DXF 配准叠加预览设计

## 背景

主流程已经逐层生成累计阈值 TIFF 和同名 Hatch DXF，并在 DXF 层选择器中逐项加入已完成文件。当前选择器只保存 DXF 路径，DXF 画布也只绘制 LINE 实体。用户虽然可以在“纹理”和“DXF”两个顶层预览标签之间切换，但“纹理”标签显示的是原始灰度输入，不能显示与当前 DXF 层对应、且经过实际裁剪或平铺的二值纹理。因此无法直观核对 Hatch 填充线是否与当前层的黑区边界对齐。

## 目标

- 在主流程 DXF 预览画布中叠加当前层对应的灰度分层纹理。
- 叠加纹理必须是实际参与 DXF 生成的裁剪或平铺结果，而不是未经变换的原始分层 TIFF。
- 切换到第 N 层时，同时切换第 N 层 DXF 和第 N 层配准纹理。
- 灰度纹理、DXF 填充线和方向箭头可以独立开关。
- 缩放、平移和适应窗口期间，纹理与 DXF 始终使用同一物理坐标变换。
- 保持现有原始纹理预览、DXF 生成、机器加工文件和独立 DXF 导入行为。

## 范围

修改覆盖主流程“灰度分层 → Hatch DXF → 加工文件”中的逐层 DXF 生成和 DXF 预览。独立“纹理转 Hatch DXF”页面只有单张输入图片，不具备灰度分层层选择器，本次不增加分层配对行为；其现有 DXF 预览保持不变。

本次不修改灰度阈值定义、Hatch 算法、Voronoi 分块、DXF 内容、侧车 JSON 或机器加工文件格式。配准 PNG 只用于界面预览，不进入机器加工文件。

## 方案选择

采用“Python 生成配准 PNG，Avalonia DXF 画布原生叠加”的方案。

`texture_to_hatch_dxf.py` 已经掌握实际生成 Hatch 时使用的目标物理尺寸、DPI、锚点、裁剪或平铺结果和阈值语义。扩展该程序，使主流程可以通过显式参数为每个 DXF 同时输出一张配准 PNG。PNG 与 DXF 使用同一目标加工区域，避免 C# 重复实现图像变换后产生偏差。

不采用 C# 重新读取分层 TIFF 并复刻裁剪和平铺逻辑，因为两套实现可能在像素取整、锚点或重复单元边界上产生细微差异。不把图片嵌入 DXF 或侧车 JSON，以免扩大加工产物、增加解析内存并混淆预览数据与加工数据。

## 配准预览生成

Python 增加一个仅在显式请求时启用的配准预览输出参数。生成流程复用 Hatch 转换已经得到的最终目标二值画布，而不是重新从源文件执行另一套变换。

配准 PNG 必须满足：

- 像素内容与生成 Hatch 时使用的最终二值掩膜一致，包括 DPI 换算、目标宽高、最小重复单元、裁剪或平铺、居中或左上角锚点、阈值及 `below-is-white` 后形成的黑白含义。
- 图片完整覆盖 DXF 的 `X = 0..目标宽度`、`Y = 0..目标高度` 物理范围。
- PNG 保留二值灰度，不加入透明度、线条或界面颜色；透明度由 C# 绘制层控制。
- 输出路径由调用方明确传入，使用与 DXF 可追溯配对的稳定名称，例如同名 `.preview.png`。
- 先写入同目录私有临时文件，成功编码并关闭后再以不覆盖方式发布，避免界面读取半成品。
- 配准 PNG 生成失败时，本层 DXF 流程按失败处理，不发布或登记不完整的产物对。

## 数据模型与配对

主流程层选择项从“显示名称 + DXF 路径”扩展为一个配对记录，至少包含：

- 层索引和显示名称。
- DXF 文件路径。
- 配准 PNG 文件路径。
- 目标物理宽度和高度。

每完成一层并验证 DXF 与配准 PNG 后，才把配对记录加入选择器。选择记录时原子地加载两者：若任一文件缺失、为空、无法解码或不符合目标边界，当前选择显示错误，并清除当前叠加纹理，绝不保留上一层纹理造成错误配对。

手动导入的普通 DXF 没有配准图片。它仍可加入选择器并正常显示，但其配对纹理路径为空，“显示灰度纹理”不可用，状态栏提示“此 DXF 没有配对纹理”。

## DXF 画布与坐标变换

`DxfPreviewControl` 在现有 DXF 线段之外持有可释放的配准位图及其目标物理边界。顶视图渲染顺序为：

1. 背景和网格。
2. 具有用户透明度的灰度配准纹理。
3. DXF 填充线和可选边框。
4. 可选方向箭头。

纹理和 DXF 共用同一个模型边界、缩放、平移和裁剪矩形。图片像素坐标 Y 轴向下，而 DXF 模型 Y 轴向上；绘制纹理时进行一次明确的 Y 翻转，使 PNG 顶边对应 DXF 的最大 Y。适应窗口以已验证的目标加工区域作为基准，不能分别适应图片和线条。

二维纹理只用于精确顶视对齐，不推断 Z 曲面映射。等轴测视图暂时不绘制纹理并在状态中提示“纹理对齐仅在顶视图显示”；切回顶视图后按原状态恢复纹理。DXF 的现有等轴测显示保持不变。

## 界面与交互

现有顶层“纹理 / DXF”标签继续保留。“纹理”标签仍用于查看原始灰度输入；新的分层配准纹理属于 DXF 核对工具，放在 DXF 标签内部。

DXF 工具区增加：

- “显示灰度纹理”复选框，配对纹理可用时默认开启。
- “显示 DXF 填充线”复选框，默认开启。
- “纹理透明度”滑块，默认 55%；纹理关闭或当前 DXF 无配对纹理时禁用。
- 现有“显示方向箭头”复选框继续保留；DXF 填充线关闭时箭头不绘制且控件禁用，但保留用户选择状态。

主流程选择第 N 层时同时加载该层 DXF 和配准 PNG。每完成一个新层，配对项立即加入选择器并自动显示，因此批处理尚未结束时也可核对已完成层。改变层、缩放、平移、适应窗口和顶视/等轴测不会修改三个显示开关的用户状态。

## 状态与生命周期

- 初始状态没有 DXF 或配准纹理，纹理开关和透明度滑块禁用。
- 开始新一轮主流程时，清空旧层选择器、DXF 线段和旧配准位图。
- 选择有效配对层后，加载两项内容并自动切到顶层“DXF”标签。
- 选择无配对纹理的导入 DXF 后，只清除配准位图，不影响 DXF。
- 取消主流程时，已经完整发布并加入选择器的配对层继续可查看；未完成层不加入选择器。
- 切换层、开始新流程和窗口关闭时释放不再使用的位图，避免长期占用原始像素内存。

## 错误处理

- Python 无法生成或原子发布配准 PNG 时，本层失败并显示具体原因，不继续登记不完整配对。
- C# 拒绝缺失、空文件、无法解码、零像素或物理宽高无效的配准图。
- 加载新层失败时清除当前纹理，状态栏同时指出 DXF 或配准图的具体失败项。
- PNG 像素尺寸不要求与物理毫米一一固定，因为 DPI 和目标取整可能改变像素密度；但宽高必须为正，且其绘制边界必须使用配对记录中的目标物理宽高。
- 独立导入 DXF 没有配准图属于受支持状态，不作为错误。
- 配准预览失败不改变已经生成的其他层，也不修改源 TIFF、DXF 或机器文件。

## 测试与验证

实现采用测试驱动方式，至少覆盖：

- Python 在居中裁剪、左上角裁剪、重复平铺及阈值方向变化时，输出 PNG 像素与实际 Hatch 使用的最终黑区掩膜一致。
- 配准 PNG 使用显式输出参数才生成；成功时完整发布，模拟编码或发布失败时不留下可用半成品。
- 主流程层项正确配对第 N 层 DXF、第 N 层 PNG 和目标物理宽高，切换选择不会串层。
- 选择无配对纹理的导入 DXF 会清除旧纹理并禁用纹理开关。
- 灰度纹理、DXF 线条和方向箭头的显示状态互不覆盖；纹理透明度正确限制在安全范围。
- 顶视图纹理的四角映射到 DXF 目标区域四角，包含 Y 轴翻转；缩放、平移和适应窗口使用同一变换。
- 等轴测隐藏纹理，切回顶视图按原开关状态恢复。
- 新流程、切层和窗口关闭释放旧位图。

完成后运行完整 Python 测试、完整 C# 测试和 Release 构建。界面验证至少选择三个黑区覆盖率不同的层，分别检查默认叠加、仅纹理、仅 DXF、透明度变化、顶视缩放和平移、等轴测提示，以及切层后纹理与 Hatch 边界仍一一对应。

## 验收标准

- 主流程选择任意已生成层后，DXF 画布默认同时显示该层实际裁剪或平铺后的灰度二值纹理与 DXF 填充线。
- 灰度纹理与 DXF 填充线可以独立开关，方向箭头保持独立控制，纹理透明度可调。
- 切换层时不会出现上一层纹理与当前层 DXF 混合的状态。
- 顶视图中纹理和 DXF 在适应窗口、缩放和平移后始终保持物理配准。
- 等轴测视图明确隐藏二维纹理，返回顶视图后恢复。
- 手动导入的无配对 DXF 继续可用，并明确说明没有配准纹理。
- 预览辅助产物不改变 DXF、侧车 JSON 或机器加工文件语义。
