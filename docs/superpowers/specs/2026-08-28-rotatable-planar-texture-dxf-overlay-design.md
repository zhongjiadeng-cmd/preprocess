# 旋转视角下的平面纹理与 DXF 配准预览设计

## 背景

主流程已经可以在顶视图中叠加当前层的配准纹理与 Hatch DXF。现有实现把 DXF 端点经过 yaw、tilt、缩放和平移投影到屏幕，但配准纹理只按顶视图的轴对齐矩形绘制，并由状态层在非顶视图中主动隐藏。因此顶视图可以核对纹理与 DXF，对画布进行等轴测或鼠标环视后则无法继续观察二者的对齐关系。

当前流程生成的是平面文件：配准纹理与 DXF 均位于 `Z = 0` 平面。未来可能增加导入带 UV 的 OBJ 并生成曲面纹理，但该能力不属于本次范围。

## 目标

- 顶视图、等轴测视图和鼠标任意旋转视角下都显示配准纹理。
- 配准纹理与 DXF 使用同一个正交投影、缩放和平移状态，旋转后仍保持物理对齐。
- 保留现有纹理透明度、纹理显示、DXF 线条显示、方向箭头、适应窗口和视角操作。
- 不改变纹理生成、DXF 生成、机器加工文件或配准元数据格式。

## 范围

本次只修改 Avalonia 主流程中的平面配准叠加预览及其状态和测试。纹理始终视为位于 `Z = 0` 的矩形平面，DXF 继续按文件内坐标绘制。

本次不导入或解析 OBJ、STL、高度图或三维网格，不推断曲面高度，不生成曲面纹理，也不为未来曲面映射预先引入模型接口。后续 OBJ 曲面功能应另行设计，并使用 OBJ 的几何、三角面和 UV 作为真实曲面来源。

## 方案选择

采用“共享正交投影的单次仿射纹理绘制”方案。

当前 `DxfPreviewControl` 对 `Z = 0` 平面的投影是二维仿射变换：模型平面上的矩形在任意 yaw 和 tilt 下投影为平行四边形。绘制纹理时构造与 `Project`、当前 scale 和 center 等价的 Avalonia 仿射矩阵，在该矩阵下绘制原始位图矩形。DXF 端点继续经过现有 `ToScreen`，两条路径共享同一投影参数和坐标约定。

不采用纹理网格细分，因为平面正交投影无需细分，逐三角形绘制会增加拼缝和维护成本。不改用 Three.js/WebGL，因为当前 Avalonia 二维绘图后端已经能够表达所需仿射变换，引入另一套渲染系统会扩大范围且不能直接服务当前桌面控件。

## 坐标与绘制

配准 PNG 的像素坐标 X 向右、Y 向下；DXF 模型坐标 X 向右、Y 向上。纹理绘制先把源位图映射到 `_textureBounds` 的物理范围，并明确翻转 Y，使图片顶边对应 `RasterTopMm`、底边对应 `RasterBottomMm`。

随后对纹理应用与 DXF 相同的模型到屏幕变换：

1. 以 `_modelBounds.Center` 为旋转中心。
2. 使用当前 `_yaw` 和 `_tilt` 对 `Z = 0` 平面执行现有正交投影。
3. 使用 `CalculateScale()` 得到的同一 scale。
4. 使用 `Bounds.Center + _pan` 得到的同一屏幕中心。

纹理的四个物理角在屏幕上必须分别等于对相同 `(x, y, 0)` 调用 `ToScreen` 的结果。纹理仍裁剪在 `_textureFrameBounds` 对应的旋转后平行四边形内，不能退化为屏幕轴对齐包围盒裁剪，否则在倾斜视角会显示加工范围外的纹理。

绘制顺序保持为背景与网格、配准纹理、DXF 线条、方向箭头。纹理与 DXF 共面时，Avalonia 的顺序绘制不会产生三维深度闪烁；透明度继续由现有 `TextureOpacity` 控制。

## 状态与交互

`DxfOverlayState.ShouldDrawTexture` 只取决于纹理是否可用以及用户是否开启纹理，不再取决于是否处于顶视图。`ShowTexture` 的用户选择在视角切换和环视期间保持不变。

有配对纹理时，状态文字统一显示“已加载配准纹理”；不再显示“纹理对齐仅在顶视图显示”。无配对纹理时继续显示“此 DXF 没有配对纹理”。现有顶视图、等轴测、鼠标环视、滚轮缩放、中键平移和适应窗口行为不变。

接近侧视时，平面在屏幕上的投影高度可能趋近于零，这是正交观察平面的预期结果。现有有限数值检查和线段裁剪继续保护绘图后端；本次不人为限制旋转角度，也不把极薄侧视图放大成错误几何。

## 组件边界

- `DxfOverlayState`：决定纹理、线条和方向箭头的可见性，不再包含“非顶视图隐藏纹理”的策略。
- `DxfPreviewControl`：提供平面模型坐标到屏幕坐标的共享投影，并在仿射矩阵下绘制和裁剪纹理。
- `MainWindow`：继续编排现有按钮、复选框、透明度滑块和状态文字，不承担投影计算。
- 测试项目：验证状态规则和纯坐标变换契约；不依赖人工查看像素作为唯一证据。

## 错误处理

- 纹理文件、像素尺寸和配准尺寸继续使用现有加载验证。
- 投影参数或矩阵元素不是有限数值时跳过纹理绘制，避免向 Skia 传入无效坐标；DXF 的现有保护保持不变。
- 无配对纹理的普通 DXF 继续只显示线条，不视为错误。
- 旋转到近侧视造成纹理视觉上变薄属于正常视角结果，不显示误导性错误。

## 测试与验证

实现采用测试驱动方式，至少覆盖：

- 有纹理且用户开启时，顶视图和非顶视图都允许绘制纹理。
- 用户关闭纹理或纹理不可用时，任何视角都不绘制纹理。
- 顶视图中纹理四角继续映射到现有目标区域四角，并保持 PNG 的 Y 翻转。
- 等轴测及一般 yaw/tilt 下，纹理四角的矩阵结果与相同物理坐标的 DXF `ToScreen` 结果在容差内一致。
- 旋转后的裁剪区域使用四边形投影，不泄漏到其屏幕轴对齐包围盒的角部。
- 缩放、平移和适应窗口对纹理与 DXF 使用相同状态。
- 状态文字不再声称纹理仅在顶视图显示。
- 现有纹理透明度、线条开关、方向箭头、纹理加载、DXF 加载和主流程层切换测试保持通过。

完成后运行完整 C# 测试和 Release 构建。界面验证至少检查顶视图、等轴测视图、两个任意斜视角和接近侧视角，并分别操作缩放、平移、适应窗口、纹理开关、DXF 开关及透明度滑块。

## 验收标准

- 配对纹理在顶视图、等轴测和鼠标旋转后的任意视角中持续可见。
- 任一视角下，纹理边界和内部图案与对应 DXF Hatch 线保持同一平面投影，不发生独立缩放、偏移、翻转或旋转。
- 旋转后加工范围外不出现由轴对齐裁剪造成的纹理泄漏。
- 现有预览交互和显示开关保持可用，状态文字准确。
- 当前实现只表达平面预览，不引入 OBJ 或曲面映射假设。
