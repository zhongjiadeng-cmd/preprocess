# 纹理图片预览与尺寸自动换算设计

## 目标

在主流程和“纹理转 Hatch DXF”页面导入纹理图片后，立即显示图片预览、像素尺寸、DPI 和换算后的物理尺寸，并根据图片的像素尺寸与 DPI 自动填写目标宽度和目标高度。

目标宽高在自动填写后仍允许用户手动修改。

## 范围

本次修改覆盖两个同时包含纹理输入和目标宽高设置的页面：

- 主流程“灰度分层 → Hatch DXF → 加工文件”
- “Texture to Hatch”独立页面

单独的“灰度图分层”页面没有目标宽高参数，不在本次修改范围内。Python 转换算法和现有转换命令参数保持不变；纹理脚本只新增一个返回图片信息的只读命令模式。

## 方案选择

使用 Avalonia 自带的图片解码能力生成预览位图，同时调用现有 Python/Pillow 读取像素尺寸与真实 DPI 元数据。该方案能够可靠地区分“图片确实设置为 96 DPI”和“图片没有 DPI 元数据”，并确保界面显示与转换后端采用完全相同的 DPI 语义。

不采用以下方案：

- 仅使用 Avalonia：预览能力足够，但其 Skia 图片实现不会保留文件 DPI，而是固定报告 96 DPI。
- ImageSharp：其通用图片元数据在没有分辨率标签时也会提供默认 96 DPI，不能对所有支持格式可靠区分“真实 96 DPI”和“未设置 DPI”。

纹理脚本新增只读的图片检查模式，以 JSON 输出像素宽高及可选的 X/Y DPI。该模式复用 Pillow 的读取语义，不生成文件，也不修改输入图片。界面预览仍使用 Avalonia 位图。

## 界面设计

两个页面各增加一个复用样式的纹理预览信息卡片。卡片包含：

- 保持原始宽高比的图片预览，限制最大显示高度，避免挤压参数区域。
- 像素尺寸：`宽 × 高 px`。
- DPI：有效时显示 `X × Y DPI`，无有效元数据时显示“未提供”。
- 物理尺寸：可以计算时显示 `宽 × 高 mm`，否则显示“等待填写 DPI”。
- 解码或读取失败时显示简短、明确的错误状态。

目标宽度、目标高度控件保留现有可编辑状态。自动换算只会在以下事件发生时写入控件：

1. 成功导入一张带有效 DPI 的新图片。
2. 当前图片没有有效 DPI，用户填写或修改有效的备用 DPI。

因此，用户手动修改目标宽高后，不会被无关的界面更新覆盖。

## 数据模型与组件边界

新增一个小型图片信息模型，映射 Python 检查命令返回的 JSON，并保存：

- 解码后的像素宽度和高度。
- 图片元数据中的 X/Y DPI。
- 当前是否需要使用备用 DPI。
- 可选的错误状态。

新增独立、可测试的物理尺寸换算函数：

```text
宽度（mm） = 像素宽度 ÷ X DPI × 25.4
高度（mm） = 像素高度 ÷ Y DPI × 25.4
```

Python 图片检查函数只负责读取输入图片并返回结构化信息。C# 图片信息读取和毫米换算不依赖具体页面控件。界面辅助逻辑接收页面对应的预览控件、信息文本、DPI 输入框和宽高输入框，负责把同一套行为复用到两个页面。

## 数据流

### 导入带有效 DPI 的图片

1. 用户选择图片。
2. 界面释放上一张预览位图并清除旧状态。
3. Avalonia 解码新图片用于预览，现有 Python 脚本通过 Pillow 读取像素尺寸与 X/Y DPI 元数据并返回 JSON。
4. 显示预览和图片信息。
5. 按两个方向各自的 DPI 计算毫米尺寸。
6. 自动更新目标宽度和目标高度。
7. 运行转换时继续使用图片内置 DPI；备用 DPI 字段不改变现有 Python 优先级规则。

### 导入没有有效 DPI 的图片

1. 显示预览和像素尺寸。
2. DPI 显示为“未提供”，物理尺寸显示为“等待填写 DPI”。
3. 保留目标宽高当前值，不使用猜测的默认 DPI。
4. 用户填写有效的备用 DPI 后，以相同的 DPI 计算两个方向的物理尺寸并更新目标宽高。
5. Python 转换阶段通过现有 `--dpi` 参数使用该备用 DPI。

### 用户手动覆盖目标尺寸

自动填写完成后，用户可以直接修改目标宽高。除非重新选择图片，或在缺少内置 DPI 时修改备用 DPI，否则不会再次自动写入这两个控件。

## 异常处理与资源管理

- 图片无法解码、格式不受支持、Python 不可用或文件读取失败时，清除预览并显示错误信息，不让异常退出应用。
- 失败的图片不触发目标宽高自动更新。
- 更换图片和窗口释放时清理旧位图，避免连续导入造成位图资源累积。
- DPI 必须为有限且大于零的数值；无效 DPI 不进行换算，继续沿用现有运行前校验提示。
- 自动计算结果按目标宽高控件支持的精度显示，并限制在控件允许的范围内；无法落入范围的结果显示错误且不覆盖现有值。

## 测试与验证

实现采用测试驱动方式。自动化测试至少覆盖：

- Python 图片检查命令对带 DPI、无 DPI 和横纵 DPI 不同图片的 JSON 输出。
- 正常 X/Y DPI 的毫米换算。
- 横纵 DPI 不同的图片分别按各方向换算。
- 缺少 DPI 时不自动修改目标宽高。
- 缺少 DPI 后输入有效备用 DPI 会自动换算。
- 零值、负数、非有限 DPI 被拒绝。
- 超出目标控件范围的尺寸不覆盖现有值。
- 用户手动修改的宽高不会被无关状态更新覆盖。

完成后运行 C# 测试、完整 Python 测试套件以及 macOS Avalonia 项目的 Release 构建。还需手动检查两个页面的预览比例、信息文案、换图后的资源替换和输入交互。

## 验收标准

- 两个目标页面选择支持的纹理图片后均能看到等比例预览。
- 页面显示准确的像素宽高和有效 DPI；缺少 DPI 时明确提示。
- 有有效 DPI 时，目标宽高立即按公式自动更新。
- 缺少 DPI 时，输入有效备用 DPI 后立即自动更新目标宽高。
- 自动值可被用户手动修改，且不会被无关操作覆盖。
- 损坏图片不会导致应用退出，也不会用错误数据覆盖目标宽高。
- 原有纹理转换参数和 Python DPI 优先级行为保持兼容。
