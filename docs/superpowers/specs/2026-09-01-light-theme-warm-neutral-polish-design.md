# 浅色主题暖中性配色精修设计

日期：2026-09-01  
状态：设计已确认，等待书面规范复核  
适用项目：`GrayscaleLayersMac`

## 背景与目标

当前浅色主题同时使用暖米色窗口底、冷蓝灰检查器与输入区、近纯白卡片，色温与明度层级相互割裂。此次精修采用已确认的“A · 暖中性统一”方向，在不改变布局、尺寸、交互和业务行为的前提下，让浅色模式更接近 macOS 的温润中性灰，并保留专业工具所需的清晰层级。

## 方案范围

- 只调整 `UiTheme.LightPalette` 及其相关浅色主题测试。
- 深色调色板、控件结构、布局、尺寸、字体、文案、功能和数据颜色保持不变。
- 不新增阴影、材质、动画、组件或设置项。
- 不在具体窗口或控件中新增主题相关 RGB 硬编码。

## 色彩方向

### 表面层级

- `Root`：由偏黄米色收敛为淡暖灰，作为整窗背景。
- `Header`：使用柔和暖白，与窗口底轻微分层但不形成突兀白条。
- `Panel`：右侧检查器改为近中性暖灰，移除明显蓝色倾向。
- `Card` 与 `Popup`：使用接近白色的暖中性色，保持内容卡片和菜单的前景层级。
- `Bar`：采用介于顶部栏与卡片之间的浅暖灰，用于工具条和固定操作区。
- `Sunken`：输入区与预览画布使用较深的中性灰，继续表达下沉关系，但避免灰蓝色块过重。

实现时以已确认的视觉方向为准，建议基础值围绕以下色组微调：窗口 `#F3F2EF`、顶部 `#FAF9F7`、检查器 `#EFEEEB`、卡片 `#FDFCFB`、下沉表面 `#ECEBEA`。最终取值必须同时通过对比度测试和应用截图复核。

### 文字、边框与状态

- 主文字、次要文字与蓝色强调色保持现有识别度，不因暖化而降低信息清晰度。
- `TextFaint` 与 `TextDisabled` 只做必要的中性化，禁用项必须可辨认但不抢占视觉焦点。
- 轻、中、强边框从偏蓝黑透明色改为低饱和暖灰透明色，维持三档强度关系。
- `Ghost`、悬停、按下、选中和禁用背景同步中性化，避免静态界面统一后交互状态重新出现冷蓝灰。
- 焦点环、危险、警告、成功和信息色继续使用现有语义角色；只有在新表面上对比不足时才做最小调整。

## 代码边界与数据流

`UiTheme.ApplyScheme` 继续根据 `AppColorScheme` 选择调色板，并更新现有共享画刷实例。组件仍只消费语义画刷，因此切换主题时不重建窗口、不影响焦点、滚动位置、表单值或预览状态。本次不改变这一数据流，只替换浅色调色板的值。

## 错误与回退

- 浅色新颜色若未满足既有对比度阈值，应优先调整对应语义令牌，不降低测试标准。
- 若视觉截图显示表面层级不足，应仅在已列出的浅色表面和边框角色内微调，不扩展到布局或组件重构。
- 外观设置解析与系统主题回退沿用现有行为。

## 验证

1. 更新或补充主题令牌测试，确认浅色画刷实例和语义角色完整。
2. 运行 `UiThemeContrastTests`，确保主要文字至少 7:1、普通文字至少 4.5:1、焦点环和强边界至少 3:1。
3. 运行完整的 `GrayscaleLayersMac.Tests`，确认深色模式和业务 UI 合约无回归。
4. 构建 macOS 应用，在与参考截图相近的窗口尺寸下检查浅色默认状态。
5. 视觉复核顶部栏、预览画布、参数检查器、卡片、输入框、禁用项、底部执行区之间的色温与明度层级。

## 完成标准

- 浅色模式整体呈现统一的暖中性灰，不再出现暖背景与冷蓝灰侧栏明显冲突。
- 卡片、输入区、预览区和边框仍具有可辨认的层级。
- 主次文字、禁用文字、输入边界、焦点环和主按钮满足既有对比度要求。
- 深色主题及所有布局、交互和业务行为保持不变。
- 自动化测试通过，并提供浅色主题截图供最终确认。
