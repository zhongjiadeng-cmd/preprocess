# 删除黑色阈值输入框设计

## 目标

从两个 Avalonia 页面中删除“黑色阈值（0–255）”输入框，并删除应用层读取该控件及向 Hatch 脚本传递 `--threshold` 的逻辑。灰度分层生成的 TIFF 已经是 0/255 二值图，因此不再让用户配置这个重复参数。

## 范围

- 删除独立“Texture to Hatch”页面中的黑色阈值控件。
- 删除“灰度分层 → Hatch DXF → 加工文件”页面中的黑色阈值控件。
- 删除 `MainWindow.cs` 中两个控件字段、变量读取和两处 `--threshold` 参数传递。
- 保留 `texture_to_hatch_dxf.py` 的 `black_threshold` API 与 CLI 默认参数，以保持脚本层兼容性；应用不再显式传递该参数，脚本继续使用默认值 128。
- 调整两处参数网格布局，避免删除控件后留下空白或错位。

## 方案

采用最小范围的 UI 与应用调用链清理。独立 Hatch 页面和流水线页面均不显示阈值设置；Python 脚本仍保留默认阈值能力，便于已有命令行用户继续使用。由于分层 TIFF 的像素只可能是 0 或 255，默认阈值 128 对现有流水线输出的识别结果不产生变化。

## 验证

- 搜索确认 `MainWindow.cs` 不再包含两个黑色阈值字段、变量读取或 `--threshold` 参数传递。
- 运行现有 Python 灰度分层测试。
- 构建 Avalonia 项目，确认 C# 编译通过。
- 检查两处参数布局在删除控件后仍完整排列。
