# PMT 节点工作流

应用默认进入“节点工作流”。“加工流程”标签保留现有工具和历史 PMT 编辑入口。两种工作区统一使用紧凑工业界面，深色为石墨灰、浅色为冷灰；右上角外观菜单支持跟随系统。

顶部第一栏管理项目与输出目录，第二栏添加节点、编辑布局及运行。右侧检查器分组显示节点属性、输出层与加工参数；标题栏显示当前选中对象。

检查器默认展示常用参数。高级分块与纹理、高级激光参数、PMT 参数覆盖及操作说明可展开查看；修改参数后展开状态保留。PMT 参数覆盖标题显示已覆盖的项目数量。文件完整路径与简短说明可悬停查看。

## 从 TIFF 到 PMT

1. 将 TIFF 拖进画布，或点击“纹理”。纹理节点显示预览，检查器提供图像信息；缺少 DPI 时使用节点中的备用 DPI。
2. 选中纹理后点击“灰度分层”，会创建并连接下游节点。依次添加 DXF Hatch 和 Machine 也会自动连接类型匹配的选中节点。也可从节点右侧圆点拖线到下游左侧圆点。
3. 在检查器中设置灰阶区间、层数，以及 Hatch 的物理尺寸、线间距、层间角度和 Voronoi 分块参数。分块数量为 0 时关闭分块。
4. 选择输出目录，点击“运行到选中节点”。程序自动执行需要更新的上游，成功结果可复用；修改输入、参数或层选择会使下游待重新运行。
5. 选中 Hatch，点击“创建单个 PMT · 全部层”或“创建单个 PMT · 选中层”。画布会增加可见的 Machine 节点和一个 PMT 工件。所选多层共同组成一个 PMT。
6. 选中 PMT 并运行，输出独立加工文件、`allmachine.json`、`patches/`、参数映射和布局。生成前继续使用现有 C# 与 Python 编译、几何校验及加工包验证。

也可导入已有 `machine.json` 与 `patches/` 目录作为 Machine 来源。此类来源的基础参数来自已有文件，在下游 PMT 中可以覆盖。

## 选择部分层

灰度分层和 Hatch 各有“全部层”与“选中层”两个输出圆点。先运行对应节点，再在检查器勾选需要的层，从“选中层”圆点拉线。不同连接可携带不同层组。

点击连线中部标签可重新编辑层选择或删除连接。“全部层”会随上游更新；选定层按稳定身份保存，仍按源层顺序传递。选择中的层消失时会明确报错，不自动替换成其他层。

Hatch 角度保留源层序号语义，挑选子集不会重新计算层号。Machine 对传入的层依次进给，不补齐被跳过层的深度。每层始终携带完整的分块信息。

## 单个 PMT 和矩阵

点击工件内部的 PMT 可编辑其 X/Y、尺寸和激光参数。尺寸是实际加工尺寸；它可相对来源几何缩放。参数留空时继承 Machine，填写时只覆盖当前 PMT。

选中一个 PMT，点击“矩阵工件”。选择行列、间距和工件尺寸，确认后创建新工件。原 PMT 保留，矩阵中每个实例继承模板尺寸和参数，并获得独立 ID 与编号。实例位置可在画布上拖动，也可精确输入。

越界与正面积重叠在画布中标红，并阻止加工输出。删除一个 PMT 不会重新排列其他对象。生成矩阵、粘贴和一次连续拖动均可一步撤销。

## 画布和快捷键

- 拖动空白处或按鼠标中键平移，滚轮以鼠标位置为中心缩放，按 F 或点击“适应全部”查看整个图。
- 拖动节点标题或空白区域移动；Shift 点击多选节点后一起移动，Cmd/Ctrl+A 选中全部节点。
- 每个节点的右下角均可拖动调整大小，预览和工件视图随之适配。右侧“画布位置与大小”可精确输入 X/Y 和尺寸，也可恢复默认大小。画布尺寸不改变实际加工尺寸或已有加工结果。
- 两种工作区使用相同的细分隔条。拖动调整左右面板宽度，方向键可微调；两侧保留最小宽度，拖到极限或缩小窗口也不会丢失分隔条。
- Cmd/Ctrl+C、V：复制、粘贴节点、单个 PMT 或工件。
- Cmd/Ctrl+Z：撤销；Cmd/Ctrl+Shift+Z 或 Ctrl+Y：重做。
- Delete/Backspace：删除选中对象；Escape：取消当前移动、尺寸调整或连线。一次连续移动或调整大小均可一步撤销。

文本框聚焦时快捷键作用于文本。粘贴会复制选区内部连接；PMT 保留有效 Machine 来源引用。处理节点不会自动复制选区外上游，缺少输入时需要重新连接。

## 保存与运行结果

“保存项目”保存版本化的 `.pmt-workflow.json`，包含节点、设置、层选择、连接、工件、PMT、编号状态及视口。项目文件引用原始纹理和导入的 Machine 路径，移动原文件后需要重新导入。打开项目后，运行会重新核对来源并生成结果。

打开其他项目遇到未保存修改时，会出现统一主题的确认浮窗。选择“继续编辑”或按 Esc 返回当前项目；选择“放弃并打开”后再挑选其他项目。

每次需要重新执行时使用新的唯一输出子目录；不会覆盖历史加工结果。取消或失败会保留已完成结果及本轮工作目录，编辑撤销不会删除磁盘文件。运行期间修改配置不会把旧结果标记成新配置的成功结果。

## 开发验证

```bash
PMT_WORKFLOW_PYTHON=/usr/bin/python3 dotnet test tests/GrayscaleLayersMac.Tests -p:UsedAvaloniaProducts= -p:UseSharedCompilation=false
python3 -m pytest tests -q
dotnet run --project tools/ProcessingWorkflowQa -p:UsedAvaloniaProducts= -p:UseSharedCompilation=false -- artifacts
```

`PMT_WORKFLOW_PYTHON` 指向带 NumPy 和 Pillow 的 Python；未指定时仅跳过真实加工集成测试。界面 QA 在独立 headless 进程运行，模拟端口拖线、节点移动、撤销重做、复制粘贴和输入框焦点隔离，并导出布局截图。
